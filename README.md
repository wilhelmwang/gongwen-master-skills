**中文公文写作的 Agent 技能包。装好即用，说人话就能出稿，每条引用都能回到原文。**

## 一、这是什么

一套以 Markdown 指令 + Python 检索引擎构成的公文写作技能，可装进 WorkBuddy、Claude、豆包等支持 Agent Skills 的平台。装好后直接说「写份通知」「起草领导讲话」「润色这段」「质检这篇公文」，技能自行判断文种、加载对应规则、必要时检索原文。

**它不是提示词模板。** 模板给你一段话让你自己改；这套东西有 14,933 篇政策文件做底、有 16 个文种的结构骨架、有可执行的自检与评测。写完能查、查完能溯源。

## 二、功能清单

### 2.1 十六个文种，各有独立骨架

每个文种是一个独立模块，内含结构模板、要素清单、常见病症、范例拆解：

| 类别 | 文种 | 产出要点 |
|---|---|---|
| 法定公文 | 通知 | 事项、依据、执行要求、时限 |
| | 报告 | 工作进展、问题、下一步 |
| | 请示 / 批复 | 一文一事、请示事项明确；批复对应作答 |
| | 通报 / 简报 / 专报 | 情况概述、典型剖析、要求 |
| | 会议纪要 | 议题、决定事项、责任分工 |
| 事务文书 | 讲话稿 | 称呼、形势、任务、要求、结语 |
| | 工作汇报 / 总结 | 成绩数据化、问题具体化、打算可执行 |
| | 调研报告 | 背景与方法、现状、问题、对策 |
| | 工作方案 | 目标、任务分解、保障措施 |
| | 经验材料 | 做法、成效、启示 |
| | 制度规定 / 办法 | 总则、分则、附则，条款化表述 |
| | 任免通知 | 依据、决定、附注 |
| | 信函 / 公开信 | 对象感、事由、诉求 |
| | 新闻稿 / 消息 | 导语、主体、背景 |
| | 心得体会 | 学习收获、联系实际、今后打算 |
| | 理论文章 | 立论、分论点、论证、收束 |

### 2.2 文风体系：两套风格库 + 会诊

- **政务六风**（`govdoc-styles` v6.9.0）：庄重简练、平实叙述、理性论证、动员感召、调研白描、政策阐释
- **书籍九风**（`shuji` v6.8.0）：置身事内体、账本体、以利为利体、小镇喧嚣深描体、中县干部体、结构性改革体等
- **多笔会诊**：同一题目按三种文风各写一版，交叉比对后取长补短
- **文风学习**：可导入本单位历史公文，蒸馏出专属风格（`govdoc-style-learn`）

### 2.3 润色与质检

- **五段式质检报告**：事实核验、表述规范、结构完整、语言硬伤、风险提示
- **易混词对照 4,272 组**：如「权力/权利」「截止/截至」「法制/法治」逐条提示
- **错别字、标点、口径一致性**检查
- **改写而非重写**：保留信息密度与原有事实，只压冗余、正语序、换表述

### 2.4 排版与导出

- **GB/T 9704 版式审计矩阵 45 条**：版头、主体、版记三段逐项核对
- 字体字号、行距、页边距、页码位置按标准版式生成
- 导出 `.docx`（`python-docx`），可直接进 OA 流程

### 2.5 以稿写稿

`govdoc-material`：给一份旧材料（总结、汇报、领导讲话），抽取可用事实与数据，按新文种重组。适合「去年的总结改成今年的汇报」这类高频场景，不必从零起稿。

### 2.6 单位私有语料接入

`govdoc-corpus`：把本单位历年公文导入本地语料库，形成可检索的文风参照。**全程本地处理，涉密件禁止导入**，导入前有范围与脱敏检查。

### 2.7 流程场景编排

`govdoc-workflow`：面向「立项报批」「预算申请」「技评财评」「某事怎么办」这类跨环节任务，先列节点清单，再逐个节点调用对应文种技能，最后串成一套材料，避免只写单篇、漏掉配套文书。

### 2.8 文章审查

`article-review`（v6.8.1）两种模式：

- **A 深度分析**：拆解论点、论据、结构，指出逻辑漏洞
- **B 事实核查**：原子声明分解 → 逐条取证 → 证据分级 → 结论对比表

内部由 1 名主理人 + 5 名专员分工，事实与逻辑分离核查，避免同一角色既挑错又打分。

### 2.9 检索与数据中枢

`qiushi-db`：把「写什么」和「依据什么」打通。

- **三种检索模式**：TF-IDF、BM25、混合排序（hybrid3，可叠加向量语义路）
- **定向下钻**：按文种、发文机关、年份、来源筛选
- **原文回溯**：每条结果带标题、机关、日期、链接，可直接核对

## 三、训练语料与知识来源

本项目的写作规则、文风模型与论断库不是拍脑袋写的，而是从权威理论刊物与政策文本中**训练与蒸馏**出来的。这是它和普通公文提示词最根本的区别：别人给你一段模板，这里给你一套从数千万字语料里长出来的判断力。

| 语料 | 规模 | 在本项目中的用途 |
|---|---|---|
| 《求是》《红旗文稿》 | **5,820 篇 / 2,697 万字** | 文风与论证范式蒸馏、论断与金句抽取、规范表述比对 |
| 领袖讲话与报道库 | 14,901 篇 / 2,458 万字 | 权威表述溯源、提法核对 |
| 政策与制度专著 | 11 本 / 92 章 / 304 万字 | 治理逻辑与行文结构蒸馏（九种书籍文风） |
| 国务院公报 | 14,863 篇 / 6,670 万字 | 文种骨架、条款化表述、随包检索 |

**蒸馏产物**

- 论断库 **31,315 条**，每条可回溯到原文
- 金句库 **31,315 条**，分排比、号召、对仗、论断四型
- 16 个文种的结构模板、6 种政务文风、9 种书籍文风
- 48 条路由回归用例、26 条写作与检索评测任务

**为什么这构成特色**

公文写作的难点不在辞藻，在「这个提法对不对、这个分寸过不过」。靠通用大模型写，容易写出看着像、实则不合口径的句子。以《求是》《红旗文稿》这类文本为底座，模型学到的是**权威表述的句法结构、论证层次与用词边界**，落笔时更接近机关文稿的实际语感。

**边界说明**

- 上述前三类语料**不随仓库分发**，版权归原权利人；仓库只提供抓取工具，见 [EXTERNAL_CORPUS.md](EXTERNAL_CORPUS.md)。随包仅含国务院公报等行政性质文件。
- 本项目为个人开源项目，与《求是》杂志社、红旗文稿杂志社及任何党政机关**无隶属关系、无合作关系、未获授权背书**；提及刊名仅用于说明语料来源。
- 这里的「训练」指**规则蒸馏与检索索引构建**，不涉及对基础大模型的再训练。若你要的是「微调了一个公文模型」的说法，本项目不属此类，避免误解。

## 四、我们的特色

### 4.1 有库可查，不是靠模型背

模型会编造文号和提法，库里不会。训练语料见上一章，随包可直接检索的是 14,933 篇中央级公开文件——**14,933 篇、6,676 万字、跨 2000–2026 共 27 年，100% 带原文链接与发文机关**（明细见第五章）。

写「依据《×××》（国办发〔20XX〕X号）」时，先查再引，不凭印象写。

### 4.2 每条引用都能回到原文

不是「参考了相关资料」，而是给出可点击的 `url`、明确的 `source`、精确的 `publish_date`。成稿中的引用要经得起别人点开核对——这是公文与自媒体的根本区别。

### 4.3 一个入口，三十个模块按需加载

宿主面板里只有一个「公文大师」。内部 30 个模块平时不加载，命中意图才读取对应 `SKILL.md`。所以它既能覆盖 16 文种 + 9 文风 + 质检 + 排版 + 审查，又不会把上下文撑爆。

### 4.4 路由中枢：不用记命令

`SKILL.md` 内置 A–F 六组路由规则（文种 / 风格 / 引用 / 新手 / 动作 / 团队模式），外加语义路由兜底。你说「帮我弄个材料」它能接住，说「给领导写个汇报，要有数据」它知道先取数再写。

规则层有 **48 条回归用例**守着，改规则不会悄悄改坏路由。

### 4.5 可自检、可评测，不是黑盒

- `verify_install.py`：**20 项**安装自检（模块完整性、数据资产、依赖、版本一致性、frontmatter 规范）
- `datahub/eval/`：**26 条**写作与检索评测任务，含 judge 脚本
- `rules_regression.py`：**48 条**路由回归用例

改完能立刻知道有没有退化。

### 4.6 数据与代码分许可，边界写在纸面上

代码 Apache-2.0；随包数据只放**行政性质文件**（国务院公报等，依《著作权法》第五条不适用著作权）；期刊、图书、地方统计一律不入库，需要时用随包工具自取。

这套边界不是为了免责，是为了让使用者清楚「哪些能再分发、哪些不能」，避免下游踩坑。详见 [DATA_LICENSE.md](DATA_LICENSE.md)。

### 4.7 本地优先

除显式执行抓取命令外，默认不联网。检索、写作、质检、排版全部在本机完成，语料不出本地。

## 五、数据底座

`datahub/sqlite/gongwen_corpus.db.gz` —— 压缩 57MB，解压 200MB。

**来源构成**

| 来源 | 篇数 | 性质 |
|---|---|---|
| 国务院公报 | 14,863 | 国务院及办公厅、各部委公开发布的行政文件 |
| 国家法律法规数据库 | 50 | 法律文本 |
| 中央部委政策 | 20 | 部委规范性文件 |

**文种分布（前 8）**

| 文种 | 篇数 | 文种 | 篇数 |
|---|---|---|---|
| 制度规定 | 5,898 | 批复 | 960 |
| 通知 | 2,417 | 决定 | 611 |
| 意见 | 1,940 | 行政法规 | 548 |
| 其他 | 1,309 | 任免 | 448 |

其余为命令 328、通告公告 298、政府工作报告 38、通报 31、报告 23、贺词 14、公文 70。

**表结构**

```
articles                          正文主表（14,933 行）
├── id / title / author           标题、发文机关
├── source / data_source          来源与采集渠道
├── publish_date / issue_year     发布日期、年份
├── url                           原文链接（每条可回溯）
├── content                       正文全文
├── genre                         文种标签（15 类，100% 覆盖）
├── word_count / crawl_time       字数、采集时间
└── keywords / topic / level      扩展标签（部分填充）

articles_fts                      FTS5 全文索引（unicode61 分词）
meta                              数据说明与构建时间
```

**能回答什么**

```sql
-- 某类文种的历年写法演变
SELECT publish_date, title FROM articles
WHERE genre='通知' AND publish_date LIKE '2015%' LIMIT 5;

-- 某个提法的规范出处
SELECT title, author, url FROM articles
WHERE content LIKE '%新质生产力%' LIMIT 10;

-- 按发文机关统计
SELECT author, COUNT(*) FROM articles GROUP BY 1 ORDER BY 2 DESC LIMIT 10;
```

**已知限制**：50 条法律条目仅有标题无正文；640 条短于 200 字（多为任免、批复类简讯），做长文参考时应避开。其余 12,081 篇在 1,000 字以上。

对表结构、采集口径、检索实现或语料治理有疑问，欢迎邮件做技术交流（见文末联系方式）。

**理论刊物语料**：仓库不含《求是》《红旗文稿》正文与图书原文。需要时用随包工具自取：

```bash
python tools/fetch_corpus.py --plan      # 先看待抓期次
python tools/fetch_corpus.py --journal   # 抓取到本地库
```

抓取结果只写入你自己的数据库，供个人学习研究参考。详见 [EXTERNAL_CORPUS.md](EXTERNAL_CORPUS.md)。

## 六、快速开始

```bash
# 1. 放进技能目录
cp -r gongwen-master ~/.workbuddy/skills/
#   Claude:  ~/.claude/skills/      通用:  ~/.skills/

# 2. 解压数据（约 200MB）
python tools/unpack_data.py

# 3. 装依赖
pip install -r requirements.txt

# 4. 建索引（首次必做）
python tools/build_fts.py                            # 全文索引，约 15 秒
python datahub/scripts/qs/qiushi_engine.py reindex   # 语义索引，约 1-3 分钟

# 5. 自检
python verify_install.py
```

> 第 4 步省略也能用，但第一次检索会现场建索引，几分钟内没有任何输出，容易误以为卡死。只想快速试跑可设 `GONGWEN_FAST=1` 走全文索引快路。

## 七、怎么用

不需要记命令，直接说：

| 你说 | 它做 |
|---|---|
| 帮我写份通知，关于防汛检查 | 选通知文种 → 套结构 → 出稿 |
| 起草领导在项目推进会上的讲话 | 讲话稿骨架 + 动员文风 + 排比句 |
| 写个工作汇报，要有数据支撑 | 汇报结构 + 检索引用原文 |
| 去年这份总结改成今年的汇报 | 以稿写稿：抽事实、换口径、重组 |
| 这段话太散，帮我收一收 | 润色：保留信息密度，压缩冗余 |
| 质检这篇材料 | 五段式报告：事实/规范/结构/语言/风险 |
| 用置身事内体写产业分析 | 切换到该书文风 |
| 核查这篇文章的数据 | 事实核查模式：逐条取证、分级 |
| 立项报批要准备哪些材料 | 流程编排：列节点清单，逐项生成 |
| 一起写稿，各写一版 | 启用专家团，多版竞稿 |

## 八、工作原理

```
关键词路由（文种 / 风格 / 引用 / 新手 / 动作）
        ↓
语义路由兜底（口语化请求向量匹配）
        ↓
加载对应模块的写作规则（按需，不全量加载）
        ↓
检索数据底座，取原文与出处
        ↓
出稿 → 可选质检 → 可选排版导出
```

路由规则写在 `SKILL.md`，模块在 `references/`，每个模块只在被选中时加载。团队模式（多角色写稿）需显式点名才启用，日常单写不增加开销。

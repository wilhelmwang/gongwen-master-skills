# 公文大师 · Gongwen Master

**中文公文写作的 Agent 技能包。装好即用，说人话就能出稿。**

它不教你"公文要怎么写"，它直接写出符合机关体例的稿子——并且每一条引用都能回到原文。

## 一、它解决什么问题

写公文真正难的从来不是格式，是这四件事：

| 痛点 | 具体表现 | 本技能怎么做 |
|---|---|---|
| **不知道从哪下笔** | 领导说"写个材料"，脑子里没有骨架 | 16 文种各有写作骨架，先给结构再填内容 |
| **口径拿不准** | 一个提法不确定是不是规范表述 | 检索政策原文，按条文引，不凭印象写 |
| **文风不对味** | 写出来像自媒体，不像机关文稿 | 六种基础文风 + 九种书籍文风可切换 |
| **不敢交付** | 错别字、敏感表述、格式不合规 | 五段式质检报告 + 排版导出 |

## 二、核心能力

### 2.1 十六个文种，覆盖日常所需

法定公文与事务文书两条线都齐：

| 类别 | 文种 |
|---|---|
| 法定公文 | 通知、通报、报告、请示、批复、函、纪要、决定、意见、命令 |
| 事务文书 | 讲话稿、工作汇报、工作总结、调研报告、简报、政策解读 |

此外，心得体会、理论文章、规章制度、公开信、述职报告等体裁，由同一批模块按结构与文风规则承接。

每个文种是一个独立模块，内含结构模板、常见病症、范例拆解，按需加载，不占上下文。

### 2.2 文风可切换，不是一套腔调打天下

- **基础六风**：庄重简练、平实叙述、理性论证、动员感召、调研白描、政策阐释
- **书籍九风**：置身事内体、账本体、以利为利体、小镇喧嚣深描体、中县干部体等
- **多笔会诊**：同一题目用三种文风各写一版，交叉比对后取长补短

### 2.3 质检与排版

- 五段式质检报告：事实核验、表述规范、结构完整、语言硬伤、风险提示
- 错别字与易混词对照（4,272 组）
- 版式排版与 Word 导出

### 2.4 专家团写稿

显式说"一起写稿""各写一版""分段承包"，即启用多角色协作：总纂定调、笔手分写、佐笔补数据、评审腿挑问题。12 个角色实体定义在 `agents/`，日常单写时不启用，不增加开销。

## 三、数据底座

这是本技能与"提示词模板"的分水岭：**它有库，不是靠模型背**。

### 3.1 随包数据库

`datahub/sqlite/gongwen_corpus.db.gz` —— 压缩 57MB，解压 200MB。

| 指标 | 数值 |
|---|---|
| 文件总数 | **14,933 篇** |
| 正文字数 | **6,676 万字** |
| 时间跨度 | **2000-01 至 2026-09，共 27 年** |
| 平均篇幅 | 4,471 字 |
| 带原文链接 | 14,933 篇（100%） |
| 带发文机关 | 14,933 篇（100%） |

**来源构成**

| 来源 | 篇数 | 性质 |
|---|---|---|
| 国务院公报 | 14,863 | 国务院及办公厅、各部委公开发布的行政文件 |
| 国家法律法规数据库 | 50 | 法律文本 |
| 中央部委政策 | 20 | 部委规范性文件 |

**文种分布（前 8）**

| 文种 | 篇数 | 文种 | 篇数 |
|---|---|---|---|
| 制度规定 | 5,898 | 批复 | 960 |
| 通知 | 2,417 | 决定 | 611 |
| 意见 | 1,940 | 行政法规 | 548 |
| 其他 | 1,309 | 任免 | 448 |

其余为命令 328、通告公告 298、政府工作报告 38、通报 31、报告 23、贺词 14、公文 70。

### 3.2 表结构

```
articles                          正文主表（14,933 行）
├── id / title / author           标题、发文机关
├── source / data_source          来源与采集渠道
├── publish_date / issue_year     发布日期、年份
├── url                           原文链接（每条可回溯）
├── content                       正文全文
├── genre                         文种标签（15 类，100% 覆盖）
├── word_count / crawl_time       字数、采集时间
└── keywords / topic / level      扩展标签（部分填充）

articles_fts                      FTS5 全文索引（unicode61 分词）
meta                              数据说明与构建时间
```

### 3.3 它能回答什么

```sql
-- 某类文种的历年写法演变
SELECT publish_date, title FROM articles
WHERE genre='通知' AND publish_date LIKE '2015%' LIMIT 5;

-- 某个提法的规范出处
SELECT title, author, url FROM articles
WHERE content LIKE '%新质生产力%' LIMIT 10;

-- 按发文机关统计
SELECT author, COUNT(*) FROM articles GROUP BY 1 ORDER BY 2 DESC LIMIT 10;
```

配套的检索引擎 `datahub/scripts/qs/qiushi_engine.py` 支持三种模式：TF-IDF、BM25、混合排序（hybrid3，可叠加向量语义路）。

### 3.4 已知限制

如实标注，免得踩坑：50 条法律条目仅有标题无正文；640 条短于 200 字（多为任免、批复类简讯），做长文参考时应避开。其余 12,081 篇在 1,000 字以上。

### 3.5 理论刊物语料

仓库**不包含**《求是》《红旗文稿》等期刊正文与图书原文——这些内容有版权，不进仓库。需要时用随包工具自取：

```bash
python tools/fetch_corpus.py --plan      # 先看待抓期次
python tools/fetch_corpus.py --journal   # 抓取到本地库
```

抓取结果只写入你自己的数据库，供个人学习研究参考。详见 [EXTERNAL_CORPUS.md](EXTERNAL_CORPUS.md)。

## 四、快速开始

```bash
# 1. 放进技能目录
cp -r gongwen-master ~/.workbuddy/skills/
#   Claude:  ~/.claude/skills/      通用:  ~/.skills/

# 2. 解压数据（约 200MB）
python tools/unpack_data.py

# 3. 装依赖
pip install -r requirements.txt

# 4. 建索引（首次必做）
python tools/build_fts.py                            # 全文索引，约 15 秒
python datahub/scripts/qs/qiushi_engine.py reindex   # 语义索引，约 1-3 分钟

# 5. 自检
python verify_install.py
```

> 第 4 步省略也能用，但第一次检索会现场建索引，几分钟内没有任何输出，容易误以为卡死。只想快速试跑可设 `GONGWEN_FAST=1` 走全文索引快路。

## 五、怎么用

不需要记命令，直接说：

| 你说 | 它做 |
|---|---|
| 帮我写份通知，关于防汛检查 | 选通知文种 → 套结构 → 出稿 |
| 起草领导在项目推进会上的讲话 | 讲话稿骨架 + 动员文风 + 排比句 |
| 写个工作汇报，要有数据支撑 | 汇报结构 + 检索引用原文 |
| 这段话太散，帮我收一收 | 润色：保留信息密度，压缩冗余 |
| 质检这篇材料 | 五段式报告：事实/规范/结构/语言/风险 |
| 用置身事内体写产业分析 | 切换到该书文风 |
| 一起写稿，各写一版 | 启用专家团，多版竞稿 |

## 六、工作原理

技能本身是一套 Markdown 指令 + Python 引擎。收到请求后：

```
关键词路由（文种 / 风格 / 引用 / 新手 / 动作）
        ↓
语义路由兜底（口语化请求向量匹配）
        ↓
加载对应模块的写作规则
        ↓
检索数据底座，取原文与出处
        ↓
出稿 → 可选质检 → 可选排版导出
```

路由规则写在 `SKILL.md`，模块在 `references/`，每个模块只在被选中时加载，因此 30 个模块不会撑爆上下文。

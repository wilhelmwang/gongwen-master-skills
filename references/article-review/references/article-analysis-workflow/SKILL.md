# 文章深度分析与报告生产流程（逆向设计版）

## 适用场景

对一篇文章/案件做深度分析并产出报告。本流程来自 2026-08-14 刘瀚文案任务的 9 轮返工教训：**每次只修被点名层→循环返工**。根因是缺失需求澄清与验收标准。本流程把决策全部前置。

## 流程总览（六步）

```
0 需求澄清（5 问，5 分钟）
1 素材并行（原文 + 核查团队）
2 文体与结构（按读者定）
3 分析论证（假说-演绎）
4 图形工具（GitHub 调研先行）
5 DoD 验收（四维自查，通过才交付）
```

## 步骤 0：需求澄清（缺失会导致 80% 返工，必做）

动笔前确认 5 个问题，答案写入报告"任务启动记录"：

| # | 问题 | 决策依据 |
|---|------|---------|
| 1 | **读者是谁？** | 律师/学者/投资人/大众 → 决定文体（法律评注体/学术论文/研报体/科普体） |
| 2 | **交付物标准（DoD）？** | 四维：文体合规/证据分级/推理链完整/图形专业（见步骤 5） |
| 3 | **用什么核查模式？** | 先盘点 `~/.workbuddy/teams/`（Team 版专家团）与 `~/.workbuddy/skills/`（单 agent）——有团队版优先团队版（多角色并行、四阶段协同） |
| 4 | **用什么图形工具？** | **先 GitHub 调研再选型**（按美观度排序，不是"会不会乱"）：D2（terrastruct/d2，现代样式首选）> mermaid（平台内嵌）> 手绘 SVG（最后选项） |
| 5 | **受众的语言与术语偏好？** | 律师：IRAC/CREAC + 三级证据分级；学者：摘要/方法/论证/局限/引用 |

## 步骤 1：素材并行

- 原文抓取（WebFetch）+ 全文存档
- 核查与素材收集并行：有 Team 版核查团队 → TeamCreate + 并行派成员（内容数据/逻辑谬误/事实研判/风险评分四角色）
- 证据分级贯穿：官方通报（★）> 权威媒体（★★）> 媒体转述（★★★）> 推断（标注）

## 步骤 2：文体与结构（由读者倒推）

- 律师/学者：法律评注体（IRAC：Issue→Rule→Application→Conclusion；CREAC 复杂问题）+ 学术论文结构（摘要/方法/论证/局限/附录）
- 投资人：研报体（结论先行金字塔）
- **普通人/大众（大学背景）**：叙事主线（故事→真相→拆解→防范）+ 术语首现必解释（USDT=虚拟币、"社会工程"=像销售经营客户一样经营你）+ 反直觉结论直给（"夏家给了 300 万、孙家没给，两人都没回来——给不给钱结果一样"）+ 实操清单化（三铁律/决策树/48 小时行动表/家庭口令）+ 核查放文末附录（"这篇文章说的都是真的吗"：可信清单/存疑清单/自验证方法）
- 通用原则：Minto 金字塔（结论先行/SCQA/MECE/三节）、渐进披露、每章一句话小结

## 步骤 3：分析论证（假说-演绎法）

每个核心结论按四步呈现，杜绝"数据陈列"：
1. **核心问题**：先问"为什么"，不满足于"是什么"
2. **竞争假说**：列出所有合理解释，逐一用证据排除（Carl Sagan 多假说原则）
3. **推理链**：前提→中间步骤→结论，每环可检验；能量化就量化（期望值/不等式）
4. **可证伪点**：明确"什么新证据能推翻本结论"

## 步骤 4：图形工具（GitHub 调研先行）

- 首选 **D2**：`d2tools/d2-v0.7.1/bin/d2.exe`（Windows 安装：GitHub release 下载 windows-amd64 tar.gz 解压）
  - 圆角关键字：`style.border-radius`（不是 radius）
  - 外层 SVG 无 width → 嵌入 HTML 需补 `width="100%" style="max-width:100%;height:auto"`
  - class 样式统一节点、容器分组（虚线 stroke-dash 区分阶段）
- 备选 mermaid：`npx @mermaid-js/mermaid-cli`（Windows 需 puppeteer-config.json 指定 Edge + --no-sandbox）
- **嵌入原则（重要）**：横向流程/时间轴图优先 **CSS 组件**（flex + 圆点连接线 + 卡片），字体固定不缩放；SVG 缩放到容器宽度时字体同步缩小——横排长图（如 1800px）缩到 800px 容器后字号仅 ~7px 不可读（2026-08-14 V3.0.3 教训）。SVG 只用于宽高比接近 1:1~1:2 的图（闭环/决策树）
- 不手绘 SVG（坐标易乱）

## 步骤 5：DoD 验收（四维自查，通过才交付）

| 维度 | 检查项 |
|------|--------|
| 文体 | 符合读者预期；无营销腔/自媒体腔（"赋能/抓手/拿起来就能用/emoji 化标题"零残留） |
| 证据 | 每个事实标注来源与级别；区分事实认定/推断/推测；无"未证实当事实" |
| 推理 | 核心结论有"问题→竞争假说→推理链→可证伪点"结构；无孤立数据陈列 |
| 图形 | 专业工具渲染（D2/mermaid）；无文字错位、箭头错乱；配色克制 |

自查不通过 → 回到对应步骤修复，**不交付未通过验收的版本**。

## 步骤 6：交付方式（微信/移动端阅读场景，2026-08-14 新增）

按目标读者在微信里的阅读方式选择载体（深度研究结论）：

| 载体 | 适用 | 要点 |
|---|---|---|
| **竖版长图**（首选） | 一次性传播、给非技术人群 | 用 wechat-longimage skill；750px×2x、按章节边界切段、段长 ≤4000px、发送勾"原图" |
| **腾讯文档链接** | 正式阅读、可二次转发 | 内容转 md 导入腾讯文档，分享"获得链接可查看"；微信内自动唤起小程序 |
| **HTML 部署链接** | 同事/内部、需完整排版 | cloudstudio-deploy；注意国内服务器需备案域名，微信内置浏览器对未备案域名有拦截风险 |
| 公众号图文 | 有公众号的创作者 | doocs/md、mdnice 排版；个人订阅号日群发限 1 次 |

禁止：微信直接发 HTML/Word 文件（体验差）；长文 PDF（手机分页阅读差）。

## 报告视觉规范（2026-08-14 大众版 V3.0.x 沉淀）

| 规则 | 说明 |
|---|---|
| hero 与正文同宽对齐 | 全宽 hero + 居中正文 = 标题偏左（大屏偏 150px+）：hero 内容包 `.hero-inner{max-width:Xpx;margin:0 auto;padding:0 24px}`，与正文容器同宽同 padding |
| 双栏目录 | 长报告用左 sticky 目录 + 右正文（grid `245px minmax(0,1fr)` gap 40px），目录滚动高亮（scroll 监听 + `.active` 类）；≤900px 退回单栏 |
| 正文列宽 | 正文不要设小于列宽的 max-width（右侧留空）；~780-800px 行宽舒适，撑满列宽消除空隙 |
| 长句要点分行 | "三句话/三铁律"类要点逐条分行 + 编号徽章（`.rn` 圆角块），避免窄列随机截断句子 |
| 版本号三处同步 | 模板 title/meta/footer 版本号必须同改后再 build；只 sed 生成文件会导致版本号残留不一致（V3.0.3 教训） |
| 横向时间轴 | CSS 组件：圆点+渐变连接线+卡片（标题/日期/说明三行），琥珀色标记"悬案/警示"节点，≤600px 自动换行 |

## 版本治理（P2）

- 只保留里程碑版：V1.0 起点 / 结构定版 / 内容定版 / 最终版
- 中间修补档不归档或合并；删除旧版前请示用户（成果资产红线）

## 经验教训速查（2026-08-14 刘瀚文案）

1. 核查模块先盘点本地资产（teams/ 目录有文章核查专家团 Team 版）
2. 图丑问题：手绘→mermaid→D2 走了 3 轮；D2 一次到位
3. "深度"=论证结构（假说-演绎），不是章节数量
4. 受众错位是最大返工源：律师/学者要法律评注体，自媒体腔从文体就不合格
5. 每轮返工成本约 30 分钟，需求澄清 5 分钟——前置决策永远划算
6. 横条时间轴用 CSS 组件（SVG 缩放字小：1800px 缩到 800px 后字 7px 不可读）
7. 换读者对象 = 换文体全量重写，不是增量修补（律师版→大众版 V3.0.0 一次成型）
8. 大众版手法：叙事主线 + 术语白话 + 反直觉结论直给 + 实操清单 + 核查放附录

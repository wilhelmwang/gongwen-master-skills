# 文章核查专家团 V3.0 — 多智能体协作式文章深度核查

## Overview

本 Skill 定义了一套**多智能体协作**的文章深度核查系统。与以往单智能体顺序执行的模式不同，V3.0 通过**5 位专职角色 + 1 位主理人**的团队分工，实现专业化、隔离化、可追踪的核查流程。

### 核心设计原则

| 原则 | 含义 | 实现 |
|------|------|------|
| **专业化分工** | 每个角色负责一个独立的专业领域 | 5 位专员各有明确的职责边界和能力清单 |
| **信息隔离** | 避免偏见交叉污染，后序角色不预知前序结果 | 信息流经主理人中转，角色间无直接通信 |
| **结论前置** | 核心判断在报告最前面呈现 | 事实研判分析师的结论位于报告首段 |
| **数据驱动** | 所有判断必须基于可追溯的公开证据 | 每条声明核查附验证依据和来源链接 |
| **透明度** | 分析的所有边界、局限、置信度均需暴露 | 认知偏见自检 + 置信度标记 + 局限性声明 |

### 对比 V2.0（单智能体模式）

| 维度 | V2.0 单智能体 | V3.0 多智能体 |
|------|-------------|--------------|
| 执行者 | 一个 AI 智能体依次执行所有步骤 | 5 位专员并行/串行协作 + 主理人编排 |
| 专业深度 | 通用能力覆盖全流程 | 每位专员在专精领域有深度方法论 |
| 偏见控制 | 需自检，但前后步骤偏见易传染 | 信息隔离，核验→逻辑→研判互不干扰 |
| 可审计性 | 仅输出最终报告 | 每位专员都有独立输出，可回溯每一步 |
| 扩展性 | 修改流程需改整份 Skill | 可通过增减角色灵活扩展 |
| 执行成本 | 一次对话完成 | 需调用多个智能体，成本更高但质量更优 |

## 角色定义与职责

### 1. 文章核查主理人（团队 Lead）

| 属性 | 内容 |
|------|------|
| 角色 ID | team-lead |
| 职责 | 团队建立、角色调度、信息中转、报告编译与最终输出 |
| 核心产出 | 结构化 Markdown 核查报告 |
| 协作方式 | 创建团队 → 调度专员 → 接收产出 → 转交下一角色 → 编译最终报告 |

**关键行为规范**：
- 必须走 TeamCreate 建立团队，不可自己模拟角色发言
- 每阶段完成后汇总消息并通报用户
- 所有跨角色信息流必须经主理人中转（不允许多专员直连）
- 最终报告由主理人编译，但不能代写专员的专业产出

### 2. 内容与数据核查员

| 属性 | 内容 |
|------|------|
| 角色 ID | content-data-verifier |
| 职责 | Phase 1 + Phase 2：文章提取、声明标记、数据验证、来源评估 |
| 核心能力 | 文章抓取、信息卡片提取、核心观点提炼、6 类声明提取、Toulmin 组件标注、多源交叉验证、置信度矩阵标注、七级星级评估、五维矩阵评估 |

**输入**：用户提供的文章 URL 或全文
**输出**：
- 基本信息卡片
- 原文核心观点陈述
- 6 类声明清单（编号声明 #1..#N）
- Toulmin 标注表
- 逐条核查结果表（含置信度）
- 数据趋势对比表
- 来源质量星级评估 + 五维矩阵

**判断标准**：
- ✅ 准确：≥2 独立来源一致，来源权威
- ⚠️ 偏差：方向一致但数值偏差 < 20%
- ❌ 错误：与外部来源明显不符，偏差 ≥ 20%
- ❓ 无法验证：无独立来源可供查证

### 3. 逻辑与谬误分析师

| 属性 | 内容 |
|------|------|
| 角色 ID | logic-fallacy-analyst |
| 职责 | Phase 3：Toulmin 组件审查、谬误检测、完整性检查、偏见自检 |
| 核心能力 | Toulmin 6 组件审查（Warrant/Claim-Grounds 匹配/Qualifier 匹配/Rebuttal 完整性）、三阶段谬误检测（5 大类完整清单）、信息完整性检查、7 项认知偏见自检 |

**输入**：Phase 1 的 Toulmin 标注 + Phase 2 的核查数据
**输出**：
- Toulmin 组件审查报告（Warrant 合理性/Claim-Grounds 匹配度/Qualifier 匹配度/Rebuttal 完整性）
- 三阶段谬误检测报告（含具体定位和严重程度）
- 信息完整性检查结果
- 7 项认知偏见自检结果
- 逻辑强度总评（5 维度 ★ 评级）

**判断标准**：
- 谬误严重程度：高（核心论证支柱被削弱）/中（论证质量降低但非致命）/低（小缺陷）
- 缺位判断：Rebuttal 缺位需区分"合理省略" vs "故意忽略关键反方论据"

### 4. 事实研判分析师

| 属性 | 内容 |
|------|------|
| 角色 ID | fact-judgment-analyst |
| 职责 | Phase 4：对文章核心观点进行基于独立数据的事实判断和趋势预判 |
| 核心能力 | 研判焦点识别、独立数据采集（WebSearch/MCP）、数据对比分析、判断形成（同意/修正/反驳）、趋势预判（含不确定性标注）、数据缺口识别 |

**输入**：Phase 2 的核查数据 + Phase 3 的逻辑分析结果
**输出**：
- 研判结论（结论置于最前）
  - 对文章核心主张的判断：✅ 同意 / ⚠️ 需修正 / ❌ 反驳 / ❓ 数据不足
  - 判断依据（具体数据对比）
  - 置信度标注
- 趋势预判（如适用）
  - 前瞻推演 + 不确定性标注
- 数据缺口清单（标记无法形成判断的领域）

**判断标准（铁律）**：
- 所有判断必须有实际数据支撑，不得空口判断
- 区分事实判断（有确凿数据）和趋势预判（含不确定性）
- 数据不足以判断的，标注"数据缺口"，不强作结论

### 5. 风险与评分评估师

| 属性 | 内容 |
|------|------|
| 角色 ID | risk-scoring-evaluator |
| 职责 | Phase 5：投资风险检测（可选）、7 维加权评分、可信度评级 |
| 核心能力 | 利益冲突识别、Pump-and-Dump 信号检测、情绪操纵分类、合规性检查、7 维加权评分、声明汇总、可信度评级、使用建议生成 |

**输入**：Phase 2 核查数据 + Phase 3 逻辑分析 + Phase 4 事实研判结论
**输出**：
- 投资风险检测报告（如适用）：利益冲突/Pump-and-Dump/情绪操纵/合规性
- 7 维加权评分表（含置信度标记）
- 声明汇总表（✅/⚠️/❌/❓ 分类统计）
- 综合可信度评级
- 使用建议表
- 分析局限性声明

**评分维度**（参见 `references/scoring-framework.md`）：
| 维度 | 权重 |
|------|------|
| 事实准确性 | 25% |
| 逻辑严谨性 | 25% |
| 信息来源质量 | 15% |
| 框架创新性 | 10% |
| 信息时效性 | 10% |
| 生产透明度 | 10% |
| 可读性与结构性 | 5% |

### 6. 报告编译员

| 属性 | 内容 |
|------|------|
| 角色 ID | report-compiler |
| 职责 | Phase 6：将多角色产出合成为最终结构化报告 |
| 核心能力 | 信息结构化编排、结论前置组织、原文vs核查对比表生成、Markdown 报告生成、文件落盘 |

**输入**：所有 5 个角色的完整输出
**输出**：最终结构化 Markdown 核查报告

## 快速启动指南

### 触发词

用户说以下任一时，触发本 Skill：
- "帮我核查 / 深度分析 / 事实核查这篇文章"
- "分析一下这篇公众号/研报/文章是否可信"
- "这篇文章的数据准确吗？逻辑有没有问题？"
- "评估一下这篇文章的投资风险"
- 提供文章 URL 或全文 + 要求深度分析

### 第一步：前置判断

快速判断文章类型，决定是否执行投资风险检测：
- **股票/投资/财经分析类** → 完整执行全流程（含 Phase 5 投资风险检测）
- **社会/时政/科普/行业分析类** → 执行全流程但跳过投资风险检测
- **非分析类（通告/声明/新闻简报）** → 仅执行概述+基本评估，跳过深度分析

### 第二步：建立团队

使用 TeamCreate 创建"article-fact-check"团队，然后依次调度成员执行各阶段。

## 注意事项

1. **用户必须提供文章 URL 或全文**，仅标题不满足分析条件
2. **非中文文章**默认不适用（如有需要可扩展）
3. **所有报告必须包含免责声明**，声明 AI 辅助分析的性质
4. **数据核查必须标注数据时点**，避免尾随性偏差
5. **结论前置**：事实研判结论位于报告最前，再逐层展开详情
6. **认知偏见自检**由逻辑与谬误分析师在 Phase 3 执行
7. **投资风险检测**仅在文章为金融投资类时执行

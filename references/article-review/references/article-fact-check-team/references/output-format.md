# 报告输出格式规范 V3.1

> 本文档定义"文章核查专家团"最终核查报告的结构模板、格式规范和输出规则。

---

## 1. 核心设计原则

### 结论前置

报告采用**倒金字塔结构**：
```
最重要的信息放在最前面
     ↓
      次重要信息逐步展开
         ↓
          背景细节在最后
```

### 报告分层

| 层 | 内容 | 阅读对象 |
|----|------|---------|
| **第一层** | 事实研判结论 + 对比表 | 想看结论的人 |
| **第二层** | 核心发现 + 综合评分 | 想看摘要的人 |
| **第三层** | 数据核查详情 + 逻辑分析 | 想看证据的人 |
| **第四层** | 来源评估 + 局限性 + 免责声明 | 想看完整报告的人 |

## 3. 输出规则

### 3.1 文件路径

| 环境 | 主路径 | 回退路径 |
|------|--------|---------|
| 有 workspace | `deliverables/article-reviews/` | 当前工作区根目录的 `deliverables/` |
| 无 workspace | 用户指定目录 | 当前目录的 `deliverables/article-reviews/` |

### 3.2 文件命名

`review-{文章主题简称}-{YYYY-MM-DD}.md`

**主题简称规则**：
- 从文章标题中提取 2-4 个核心关键词
- 使用中文字符
- 主题间用短横线连接
- 示例：`review-算力租赁行云科技-2026-07-30.md`

### 3.3 报告完整性检查清单

提交报告前逐项确认：

- [ ] 事实研判结论已在最前
- [ ] 原文观点 vs 核查结论对比表已生成
- [ ] 核心发现已提炼（3-5 条）
- [ ] 所有声明已逐条核查
- [ ] 逻辑分析已完成
- [ ] 评分已完成（7 维度 × 权重）
- [ ] 声明汇总表已生成
- [ ] 置信度标记已附加
- [ ] 如适用：投资风险检测已完成
- [ ] 使用建议已提供
- [ ] 分析局限性已记录
- [ ] 数据来源索引已列出
- [ ] 免责声明已包含

## 4. 声明汇总表格式

用于报告中快速概览核查结果：

```markdown
| 分类 | 声明数 | 具体条目 |
|------|-------|---------|
| ✅ 已证实准确 | N 条 | #1, #3, #5, #7 |

| ❌ 确认不准确 | N 条 | #4 |
| ❓ 无法验证 | N 条 | #8 |
```

# 单位私有语料接入（govdoc-corpus v1.0.0）

## 角色定位

把**本单位历年公文**变成一个可检索、可学习的本地语料库，让后续写作能贴合本单位的实际写法与口径。

这是政务采购里的硬门槛能力，也是**风险最高的一项**——因为它处理的往往是内部材料。
因此本技能的第一条不是功能，是**边界**。

## ⚠️ 涉密与合规边界（先读这一节，再动手）

### 三条硬约束

1. **导入前必须提示，不可默认执行**。首次运行必须原样告知用户：

   > 本流程将在**本地**解析你指定目录下的公文并建立本地语料库。
   > **请勿导入涉密文件**（《保守国家秘密法》要求涉密信息全环节合规）。
   > 若目录中可能含涉密件，请先自行筛除。
   > 本流程**不调用任何 LLM、不发起网络请求**，解析与画像全部在本机完成。

   用户未确认前，不执行导入。

2. **解析过程不外发**。`scripts/corpus_build.py` 是纯标准库 + jieba 的本地脚本，
   **不含任何网络调用、不读 LLM 凭据**。这是本技能的合规基础，不得为"增强效果"而改动。
   若要接 LLM 做语义分析，属于另一次需要单独授权的动作，且涉密材料一律禁止。

3. **建独立库，不进合并库**。语料落用户指定的独立 SQLite（默认 `<目录>/../单位语料库/corpus.db`），
   **绝不写入 `gongwen_corpus.db`**（那是求是/地方公共语料库）。
   单位语料与公共语料物理隔离，避免后续检索把内部口径当权威表述引用。

### 一条能力边界（别夸大）

本技能只做**确定性的统计画像**（句长、结构装置、高频表述），
**不做"语义理解式"的风格提炼**。所以：

- 画像给的是"本单位常怎么写"，不是"本单位为什么这么写"
- 画像质量**强依赖样本量与文种覆盖**，脚本会给「样本充足度」评级 —— **评级不足时不要拿画像当依据**
- **画像不得直接当验收线**。小样本（精读抽样）得到的区间与全量统计差异很大，拿抽样值判合格会系统性
  冤枉好稿（实测命中率只 8%–16%）。口径、离散度、假设冲突等四条使用纪律见
  `references/param-guardrails.md`，**用画像前先读它**。

## 工作流

### Step 1 范围确认与涉密提示

1. 问清三件事：**目录路径** / **时间范围** / **要覆盖哪些文种**（默认全部）。
2. 原样给出上文第 1 条的涉密提示，等用户确认。
3. 确认后**先做一次干跑**（`--plan`）列出将处理的文件数与格式分布，让用户过目。

### Step 2 格式预处理

- `.docx` → 脚本直接解析（纯标准库）
- `.txt` / `.md` → 脚本直接读取
- `.doc` / `.pdf` / 扫描件 → **先用 `convert-documents-to-markdown` 转成 Markdown**，
  再放进待处理目录；或直接跳过（脚本会显式报告跳过清单）
- **扫描件（图片型）无法提取文字** → 必须显式报出，不得静默跳过

### Step 3 建库与蒸馏（一条命令）

```bash
python scripts/corpus_build.py --src "D:/单位公文" --out "D:/单位语料库" --plan
python scripts/corpus_build.py --src "D:/单位公文" --out "D:/单位语料库"
```

脚本产出：

| 产物 | 内容 |
|---|---|
| `corpus.db` | 独立 SQLite：逐件一行（路径/文种/年份/部门/字数/正文/txt_hash），**每件可溯** |
| `profile_文风画像.md` | 句长分布、结构装置频次、惯用开头/收尾、高频表述 |
| `profile_口径清单.md` | 实名口径（"我局""我市"）、固定表述、应避免表述 |
| `index_范文索引.md` | 按 **文种 × 年份** 的历史范文清单 |
| `build_report.md` | 处理统计、**跳过清单及原因**、**样本充足度评级** |

### Step 4 交付与使用

交付时**必须把 `build_report.md` 的跳过清单与充足度评级一并说明**，不要只报"导入成功 N 件"。

后续写作时的用法：
- 要贴合本单位写法 → 读 `profile_文风画像.md`
- 要确认本单位怎么称呼某项工作 → 查 `profile_口径清单.md`
- 要参考本单位先例 → 查 `index_范文索引.md`，再回原库取全文

## 与相邻技能的分工

| 需求 | 该走谁 |
|---|---|
| 全量历年公文批量接入 + 统计画像 | **本技能** |
| 少量精选范本 → 定制文风模板 | `govdoc-style-learn`（嵌套于 gongwen-master） |
| 有零散材料要成一篇稿 | `govdoc-material` |
| 检查某篇稿子的错别字/敏感词 | `govdoc-polish`（质检模式） |

## 红线

1. **涉密件不导入**。用户不确认就不执行；用户说"应该没涉密"时，提醒其自行确认，不代为判断。
2. **不联网、不调 LLM**。脚本的确定性是合规前提，不得为效果而破坏。
3. **不写合并库**。单位语料必须与公共语料物理隔离。
4. **不静默跳过**。无法解析的文件必须逐项报出。
5. **不夸大画像**。样本不足时明说"不足以作为依据"，不硬给结论。
6. **不拿画像当验收线**。参数与区间只能作对照；自检只判硬冲突（文种识别错误级）。
   见 `references/param-guardrails.md`。
7. **不自动改写原文**。入库的是原文；清洗只在派生统计层做（去页码/页脚等版式噪声），且原样保留 `raw`。
8. **统计数字必带来源**。每一个 n 篇 / x% 必须同节写清：数据源、样本量、脚本、复算等级（A/B/C）。
   未标注来源的统计数字按不可复核处理。见 `references/reproducibility.md`。

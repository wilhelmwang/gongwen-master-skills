# 认知层（L3–L5）：站位、弹药、分寸（cognition-layers v1.0.0）

> 前三层（参数、结构、语言）管「像不像」。这一层管**「对不对」「稳不稳」**——写作者的站位、
> 引用层级、数据位置、力度分寸、收尾方式。
> 本机数值由 `scripts/cognition_stats.py` 从**本机语料库**跑出，可复算；外部参考工程的数值
> 只作对照并已标明不可复算（见 §六）。

## 一、L3 站位：开篇最早给什么

按正文**开头 120 字里最早出现的信号**分类（不是出现最多），本机 `articles` 表 20,127 篇实测：

| 站位 | 篇数 | 占比 |
|---|---|---|
| G 其他/无显著信号 | 10,445 | **51.9%** |
| A 国家战略/全局定位 | 5,004 | 24.9% |
| B 政策依据/受命行文 | 3,904 | 19.4% |
| D 现实问题/形势警示 | 617 | 3.1% |
| E 群众感受/一线场景 | 131 | 0.7% |
| F 个人经历/白描叙事 | 24 | 0.1% |
| C 制度缺陷 | 2 | **0.0%** |

**三条判读**：

1. **一半以上（51.9%）的开篇不给显著信号**——直接切入正题。想用「某某」起手式开头的，要知道它不是主流。
2. **C 制度缺陷只有 2 篇（0.0%）**。这是最重要的一条：**优秀公文不把制度缺陷当切入点**。想谈体制问题，先垫战略定位与成效，把问题放到中段。
3. A 与 B 合计 44.3%，是主要的两条正路——**要么从全局战略切入（A），要么从政策依据切入（B）**，二者取一。

> **本机口径限制**：本表主要覆盖国务院公报、求是理论文章、习近平讲话三类，**不含**调研报告/领导讲话/工作意见/经验材料这些内部工作材料的细粒度分布。上表可作「公开话语的站位习惯」参考，**不能直接当内部材料的合格线**。

## 二、L4 引用层级：六层，顺序即权威降序

| 层级 | 内容 | 本机 `articles` 覆盖率 | 本机 `jhsjk_articles` 覆盖率 |
|---|---|---|---|
| T1 | 习近平总书记 | 36.4% | **100.0%**（该表即习近平讲话库，属定义性） |
| T2 | 党中央/全会/党代会 | 36.7% | 29.2% |
| T3 | 国务院/国家级文件 | 53.0% | 14.1% |
| T4 | 省委省政府/部委党组 | 23.4% | 4.4% |
| T5 | 法律法规 | 48.0% | 3.1% |
| T8 | 古语典故/国际比较 | 4.0% | 2.3% |

**两条使用纪律**：

1. **引用不是越多越好，是「哪一层」要对**。上行文引上级（T2/T3）交代授权；下行文引法律依据（T5）确立正当性；讲话稿引 T1 定调。
2. **具名领导的引用有清晰边界**：引本单位领导是为了**交代授权**，且要连**姓名带职务带原话**。批示属内部行文，不转录。可迁移的是「授权链降序」这条写法（上级定调 → 上级分管点题 → 本单位副职批示 → 指定报送对象），**不是被引者是谁**；照搬时换成本单位真实的授权链。

## 三、L4 弹药（数据）的位置：前半篇密集，建议段几乎无数据

本机带单位数字的十分位落点（`articles` 20,127 篇，共 149,314 个带单位数字）：

| 落点 | 占比 | | 落点 | 占比 |
|---|---|---|---|---|
| 0–10% | 8.2% | | 50–60% | 10.0% |
| **10–20%** | **11.1%（峰值）** | | 60–70% | 9.6% |
| 20–30% | 11.8% | | 70–80% | 9.4% |
| 30–40% | 11.0% | | 80–90% | 10.6% |
| 40–50% | 10.4% | | **90–100%** | **7.7%（谷值）** |

**判读**：前 20%（基本情况/成效段）占 19.3%，末 10%（建议段）仅 7.7%——**差值约 2.5 倍**。

> **建议段不摆数据，是因为建议是主张而非事实；数字的职能是奠定「我摸清了情况」的资格。**
> 在建议段堆数据，等于用事实的语气说主张。

（外部参考工程在内部工作材料上测得同向且更极端：末 10% 塌陷到 2%、中央调研报告前 20% 占 33%。本机因语料含大量政策文件，曲线比内部材料平缓——**方向一致、幅度不同**。）

## 四、L5 分寸：力度词与行文方向严格相关

### 4.1 力度词密度（每千字次数，本机实测）

| 词 | `articles`（20,127 篇） | `jhsjk_articles`（14,631 篇） |
|---|---|---|
| 要求 | 0.91 | 0.40 |
| 严禁/不得 | 0.56 | 0.02 |
| 必须 | 0.42 | 0.47 |
| 切实 | 0.18 | 0.16 |
| 建议 | 0.10 | 0.12 |
| 希望 | 0.03 | 0.39 |

**四条判读**（机制可迁移，数值按本机口径）：

1. **「建议」是上行文的专属**。有权决定的人不「建议」。外部参考工程在内部材料上测得调研报告 2.5–3.2 次/篇、工作意见 0.2、讲话 0.3——本机两条曲线都低，因本机语料以下行政策文本与讲话为主。
2. **「希望」是下行且面向不可命令对象时的唯一选项**（本机 jhsjk 0.39 vs articles 0.03，差 13 倍）。**对象决定用词：面向不是自己下属的对象用「希望」，面向本系统干部用「要」。**
3. **「严禁/不得」只在真规范性文件里密集**（本机 articles 0.56，因含大量法规原文；jhsjk 仅 0.02）。写工作意见才用，写经验材料不用。
4. **「必须」的密度看着不高（0.42–0.47），但引语中的「必须」要被剔除后再看**——照搬总书记原话里的「必须」不是作者在下命令。外部参考工程测得心得体会 2.5 次/篇，其中多是转引。

> **统计前必须先剔除引号内内容**。自造概念常带力度字样（如把需求分类命名为「必须改」「可以缓」），计入后会顶破配额。本机 `param_check.py` 与 `check_params.py` 均已在统计前做 `depunct` 剥离。

### 4.2 收尾：按行文方向编目

本机实测（末 130 字，可多重命中）：

| 收尾程式 | `articles` | `jhsjk_articles` |
|---|---|---|
| **自然收束/无程式化结语** | **94.8%** | **93.9%** |
| 讲话·号召口号 | 3.8% | 3.8% |
| 讲话·程序语 | 1.3% | 2.5% |
| 下行·落款式/督查问责 | 0.3% | 0.0% |
| 经验材料·留余地 | 0.1% | 0.0% |
| 上行·供参考（开篇式谦辞） | 0.0% | 0.0% |
| **上行·谦辞在结尾** | **0.0%** | **0.0%** |

**这是本层最反常识、也最可核验的一条**：

- **九成以上（93.9%–94.8%）是自然收束**，不加程式化结语。
- **「妥否，请批示」「请审阅」在 3.5 万篇里 0 次。** 上行文的谦辞不在结尾——它在**开篇 3%–10% 处**一次说完（「形成如下调研报告，供领导参阅」），结尾直接收在最后一条建议上，不回头行礼。
- **程式化结语按文种选**（写时才用，不是通用礼仪）：

| 行文方向 | 可用收尾 |
|---|---|
| 上行请示 | 妥否，请批示／以上请示，请予批准 |
| 上行报告 | 特此报告／以上报告，请审阅（**低频**：本机 0%，外部参考 2/226 篇） |
| 下行通知 | 请遵照执行／特此通知 |
| 平行函 | 专此函达，请予复函／特此函复 |
| 讲话稿 | 号召＋表决心（本机 3.8%） |
| 下行工作意见 | **落款式，末条多为督查问责或回流通道**（「贯彻执行中的问题请及时报部」） |
| 经验材料 | **留余地**——「取得初步成效，假以时日……」不宣称完成，只宣称起步 |

> **判据**：先看行文方向，再决定要不要结语。**没有方向的「加一句得体的话」是 AI 味的典型来源。**

## 五、一条横向纪律：成绩外部化，问题两分法

外部参考工程在 226 篇内部工作材料上提炼的归因机制（**机制可迁移，数值不可复算**）：

- **成绩一律外部化、上溯化**，句式高度固定「在……领导/支持下」。抽样中未见「我们创造性地开创了……」这类自我归功；自评词多是「初步」「积极成效」「明显好转」。
- **问题走两条路，严格分工**：
  - **客观化**——归给历史、地理、发展阶段、外部环境，共同点是**不含责任主体**（「由于历史和地理的原因」）。
  - **主观化**——归给思想作风，但**必须加「个别/部分/少数」限定**（「一些党员干部」「少数单位」）。
- **关键规律：凡标「根本原因」者几乎必落在思想认识上，体制机制问题被安排在「客观制约」位。** 推断：思想问题可通过教育自我纠正，属本级能承诺的范围；体制问题的解决权在上级。**把根本原因定位在思想上，等于把整改责任收进自己能兑现的边界。**
- **第三条路是稀释**——强调多因、长期、非个案（「原因是多方面的、深层次的，是长期积累形成的」）。
- **转折密度与文种相关**：需要讲问题的文种（调研报告）转折 4.4–5.1 次/篇，报成绩的文种（经验总结 0.0、工作意见 0.2）**一次都不用**。**要讲问题的文种才需要转折；报成绩的文种一次都不用。**

## 六、本机口径与不可复算声明

- **可复算的部分**：§一至 §四的所有数值由 `scripts/cognition_stats.py` 从本机
  `<数据根>/gongwen_corpus.db` 现算，命令与表名、篇数均已标注，第三方可按同口径复跑。
- **不可复算的部分**：§五 的机制来自外部参考工程 `lieflat-gongwen`（PolyForm Noncommercial 1.0.0）
  在 226 篇内部工作材料上的统计，其原始语料因版权不随包分发 ⇒ **本机无法复算那些百分比**。
  引用时只能引「机制」，不得引其数字当合格线（见 `param-guardrails.md` 第二纪律）。
- **本机语料的覆盖缺口**：`articles` 表以国务院公报（14,863）、求是系（400 余）、习近平讲话为主，
  按主题/来源组织，**不是**按「调研报告/领导讲话/工作意见/经验材料/经验总结」这些**内部工作材料文种**组织。
  因此本层数值**不能**套用到那些文种上——引用时必须写明统计来源表与篇数。
- **不联网、不调 LLM**：`cognition_stats.py` 只用标准库 + sqlite3，纯 SELECT，不写库。

## 七、引用这些结论时的三条自检

```
□ 我引的数值是哪张表、多少篇跑出来的？（没写清就是不可复核的）
□ 我引的数值对应的文种，和我正在写的文种是同一族吗？（不同族不能套用）
□ 我是在用「机制」还是在用「数字」？（机制可迁，数字必须先在本机复算）
```

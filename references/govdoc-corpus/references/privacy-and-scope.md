# 涉密判定、目录筛选与语料隔离（govdoc-corpus）

> 本技能处理的是**内部材料**，风险等级高于本包其他任何技能。
> 本文是操作前的检查清单，不是可选说明。

---

## 一、导入前的涉密检查清单

用户确认前**不执行导入**。逐项确认：

- [ ] 该目录下是否含有**密级标识**文件（"绝密""机密""秘密"字样，或在版头右上角标密级）
- [ ] 是否含有**未公开的内部决策材料**（会议纪要原件、请示批复链条、未发布的政策稿）
- [ ] 是否含有**个人信息**（人员名单、身份证号、联系方式）
- [ ] 是否含有**涉密项目/涉密场所**的相关描述

**任一命中 → 不得导入**。

### 提示话术（首次运行原样告知）

> 本流程将在**本地**解析你指定目录下的公文并建立本地语料库。
> **请勿导入涉密文件**（《保守国家秘密法》要求涉密信息全环节合规）。
> 若目录中可能含涉密件，请先自行筛选。
> 本流程**不调用任何 LLM、不发起网络请求**，解析与画像全部在本机完成。

### 用户说"应该没涉密"时怎么办

**不代为判断**。回复：

> 涉密判定应以你单位的保密审核为准，我无法替你确认。建议先由保密员确认目录内容，
> 或你自行剔除含密级标识、内部决策、人员信息的文件后再导入。

## 二、目录筛选建议

### 建议纳入

| 类型 | 理由 |
|---|---|
| 已正式发文的成文件（带发文字号与落款） | 代表本单位正式写法，画像价值最高 |
| 公开发布或已在本单位内网公开的材料 | 涉密风险低 |
| 历年工作总结/报告/通知（已成文） | 覆盖主要文种，利于体例学习 |

### 建议排除

| 类型 | 理由 |
|---|---|
| 密级标识件 | 合规红线 |
| 未定稿的草稿/征求意见稿 | 不代表正式写法，会污染画像 |
| 领导个人批注稿 | 个人信息 + 非正式表述 |
| 会议录音整理稿 | 口语化，与公文文风不符 |
| 含个人信息的名单/台账 | 个人信息保护 |

### 目录准备建议

按文种分子目录，脚本会自动识别文种（从文件名与正文），但子目录结构能让结果更可靠：

```
D:/单位公文/
├── 通知/
├── 总结报告/
├── 请示批复/
├── 会议纪要/
└── 制度规定/
```

## 三、与公共语料的隔离要求（硬性）

| 要求 | 说明 |
|---|---|
| **独立库** | 单位语料写入用户指定目录下的 `corpus.db`，**绝不写入 `gongwen_corpus.db`** |
| 物理隔离 | 两者不共库、不共索引、不共向量 |
| 不交叉检索 | 写作时引用单位口径走本地画像/索引；引用权威表述走 `qiushi-db`（求是/地方） |
| 不混入发包 | 单位语料**永不随包分发**（本包分发件只含公共语料说明，不含任何单位材料） |

**为什么必须隔离**：如果把单位内部口径混进公共语料库，后续检索可能把"我局"当成权威表述
引用到对外文稿里，属于严重事故。

脚本在输出目录名含 `gongwen` 且不含"语料"时会给出告警，但这只是提示——
**真正的隔离靠操作者选对输出目录**。

---

## 四、误导入的补救

若发现误将涉密/内部材料导入了：

1. **删除整个输出目录**（含 `corpus.db`）——不要只删行，SQLite 删除后数据仍可能在文件页里
2. 重新筛选源目录
3. 重建语料库

若该目录已被复制到其他位置，一并删除。**本脚本不做"软删除"**，就是为此——
避免让人以为删掉了其实还在。

---

## 五、能力边界（不夸大）

本技能产出的是**确定性统计画像**：

| 会给 | 不会给 |
|---|---|
| 句长分布、结构装置频次 | "本单位为什么这么写" |
| 惯用开头/收尾、高频表述 | 语义层面的风格提炼 |
| 实名口径清单（我局/我市…） | 禁用词判定（那属于 `govdoc-polish` 质检模式） |
| 按文种×年份的范文索引 | 自动改写用户的新稿 |

**画像质量强依赖样本量**。脚本按文种给出充足度评级：
`充足（≥8 件）/ 一般（3-7 件）/ 不足（<3 件）`。
**评级为"不足"的文种，画像不得作为依据**——这是硬约束，不要因为"看着挺像"就采信。

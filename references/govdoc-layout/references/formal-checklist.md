# 正式党政机关公文逐项核验表（人机协同）

> 版本 v1.0.0 ｜ 2026-09-28
> 依据：GB/T 9704-2012《党政机关公文格式》
> 用途：**机关权威模板完成后的人机协同核验**。每项记录「适用/不适用、证据位置、核验人、日期」；不适用应说明原因。
> 边界：**本表不替代发文机关公文处理制度**，也不替代核稿人终审。

---

## 0. 本批次验了什么（每次填，不得留空）

这一节是给下一个看这份表的人用的：他要能判断「上次那次『验过了』到底验到哪一层」。

| 项 | 填写要求 |
| --- | --- |
| 核验日期 | 年-月-日 |
| 生成工具与版本 | 如 `govdoc-layout / generate_docx.py` + 技能 VERSION |
| 生成命令 | 完整命令行，含 `--doc-type`、`--font-preset`、`--unsealed` 等全部开关 |
| **验证方式** | 三选一或并列：①XML 结构断言（跑了什么脚本）②PDF 渲染量测（跑了什么脚本、输出什么数）③**仅人工目视**（写清看了哪几页） |
| 渲染环境 | 目标软件与版本（Word/WPS）、操作系统、**本机实际装有的中文字体清单** |
| **本批次未验** | 明确列出。凡属本表 §6「机器不可判」的项目，若本批次未做人工核验，必须写在这里 |
| 字体替换情况 | 若本机缺方正小标宋/仿宋_GB2312 而使用了替代字体，写清替代关系并声明**不得视为达到最终打印标准** |
| 核验人 | 姓名/岗位 |

**判据**：如果这一节填不出「本批次未验」的具体项目，说明本次核验的范围没有被界定，等于没验。

## 7. 常见假通过（填表前先自查这五条）

| 假通过 | 真相 | 正确做法 |
| --- | --- | --- |
| 「XML 里有段前距，所以红线下留了两行」 | 目标软件可能忽略该段前属性 | 看**两个显式 28 磅空段落**是否存在，再看 PDF 渲染 |
| 「校验器 PASS，所以合规」 | 校验器只覆盖它自己那 21 项 | 对照 §0 写清「未验」清单 |
| 「用了宋体/仿宋，差不多」 | 字号相同、字体不同，字宽与换行会变 | 缺字体时必须声明并**不得称达到最终打印标准** |
| 「生成器会告警，所以没问题」 | 本机**没有字体可用性探测** | 先人工核对本机 `%WINDIR%\Fonts` 与用户字体目录 |
| 「版记在最后」 | 本机版记靠影子渲染估算前距，非浮动锚定 | 长文必须转 PDF 逐页看版记落点 |

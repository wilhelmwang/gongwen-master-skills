# GB/T 9704-2012 逐条执行矩阵（本机 govdoc-layout 口径）

> 版本 v1.1.0 ｜ 2026-09-30 ｜ 依据：GB/T 9704-2012《党政机关公文格式》（现行；2025-05-30 复审结论为继续有效）
> 官方信息页：https://std.samr.gov.cn/gb/search/gbDetailed?id=lOIe27f77QU%3D&mode=p
> 条文全文转载页：https://gov.cn/zwgk/2013-02/22/content_2337704.htm
>
> **本矩阵与本机代码的对应关系**：本机实现由 `scripts/docgen_export/rules.py`（常量）、`render.py`（语义 section → 段落规格）、`opc.py`（XML 与打包）、`pagin.py`（版记沉底）四层落地；另有一条与之正交的「格式档（format profile）」轴（`_FORMATS` / `resolve_format()`）；读侧由 `scripts/inspect_govdoc.py` 落地（跑出 26 条检查，分「页面与版心 / 版面网格 / 正文与标题 / 字号与落款 / 页码与版记」五组，PASS / WARN / FAIL / SKIP / MANUAL 五态）。矩阵里的「本机证据」一栏写的是**可复现的检查方式**，不是「已合规」的断言。

## 三态声明

本矩阵把每条标准要求归入三类，避免把「生成了 DOCX」写成「制作环节均已合规」：

- **机器可判**——生成器写入且体检器能逐项断言，改动即红。
- **结构可判，视觉仍需人工**——XML 结构正确，但目标 Word/WPS 的渲染、字体替换、分页仍会改变最终效果。
- **机器不可判**——纸张物性、印刷油墨、装订钉位、实体印章、机关专用模板。**这些一律不写「已通过」，只写「记录要求 + 由谁在什么条件下核」**。

## 读侧体检器的格式档适配（2026-09-30 复核）

矩阵此前只写「读侧由 `inspect_govdoc.py` 落地」，没记它对格式档的适配状态。实测如下——**这决定了「本机证据」一栏里哪些项目前真能自动判**：

- 体检器**已学会看格式档**：`_check_page(k, checks, ignores, fmt)` 与 `_check_pageno_and_endmatter(k, checks, ignores, fmt)` 均接 `fmt`；命令行有 `--format`。
- 信函档：天头期望改判 30mm；**版心高度改报 SKIP**（条款 10.1 只规定上边缘 30mm 与下页边 20mm 处双线，未重申 5.2.1 的 156×225）；新增「信函红双线页脚」与「信函首页无页码」两项。
- 横排档：页面尺寸按横向判、版心改判「版心尺寸(横排)」、新增「横排表宽」、网格检查 SKIP。
- **调用时必须带上格式档**（`--doc-type` 或 `--format`）。不给就按通用档的期望值判，对信函/横排件会误报 FAIL——这是**已知且必然**的行为，不是体检测错了。
- 体检器新增第五态 `MANUAL`（机器不可判的人工项，如印章位置、油墨色值、装订裁切、横排单双页表头朝向），**不计入退出码**；退出码只在有 FAIL 时非零。

## 本机与上游实现的差异（诊断用，不构成标准依据）

| 项 | 本机 | 上游 gongwen-gbt9704-skill |
| --- | --- | --- |

**「本机 579 vs 上游 560」的定性**：GB/T 9704-2012 5.2.3 规定的是「一般每面 22 行、每行 28 字」这一**版面结果**，未强制行距数值。本机 579 在该版面参数下推得出 22 行撑满，上游 560 推不出。**两者都不是「国标唯一强制参数」，不得把固定行距当作合规判据。**

## 用本矩阵的方式

1. 改生成器前——先查目标条款落在「机器可判」还是「结构可判/不可判」，别把归属第三类的项目写成 PASS。
2. 报「已合规」前——只允许对「机器可判」类下断言；第二类必须写「结构通过，视觉待核」；第三类写「本工具不保证」。
3. 加能力后——回来把对应行的「本机证据/缺口」改掉，缺口清空了才算该条款真的接上。
4. 把某行读成「缺口」前——**先看代码，再看本行**。本矩阵是「代码 → 条款」的映射，代码先行时矩阵会落后：一个已在运行的实现若仍被标成缺口，会让后续决策去重做已经做完的事（v8.1.7/v8.1.8 已实现的三档几何与版记锚定，在 v1.0.0 版矩阵里就仍写作「本机无」）。

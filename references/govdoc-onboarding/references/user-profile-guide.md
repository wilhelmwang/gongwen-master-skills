# 用户画像与背景沉淀规范（user-profile · v7.1.2 私人秘书化）

> 目标演进：v7.1.1「画像档案」（被动：问才答、写完存）→ **v7.1.2「私人秘书」**（主动：预告/提醒/习惯学习/代拟偏好/材料串联）。
> 三层机制：**①画像档案**（基础，保持不变）→ **②私人秘书服务层**（新增，主动式）→ **③分身份个性化引导**（保持）。

## 〇、私人秘书与画像档案的本质差异

| 维度 | 画像档案（v7.1.1） | 私人秘书（v7.1.2 新增） |
|---|---|---|
| 姿态 | 被动：问才答 | 主动：会预告、会提醒 |
| 学习 | 记录单次事实 | 学习**周期规律**（如"每月 5 号交月报"） |
| 偏好 | 存用户说过的 | 归纳**代拟偏好**直接套用 |
| 视野 | 单份材料 | **多材料串联**（知道你在做什么专项） |
| 时间感 | 无 | 有（公文日历意识：季度总结季/年底考核季） |

## 一、画像数据模型（v7.1.2 扩展段，在原 user-profile.md 追加）

```markdown
## 私人秘书服务（v7.1.2 新增）

### 公文日历（周期规律，从材料历史自动归纳）
- 每月 5 号前：月度工作报告（用户材料历史归纳）
- 每季度末：季度总结 + 下季度计划
- 每年 1 月：年度总结 + 预算申报季

### 进行中的专项（串联记忆）
- 专项名称：{如"智慧城市二期验收"}
- 关联材料：验收申请（已交）→ 整改方案（进行中）→ 总结报告（未开始）
- 下一步：assistant 应主动提示"整改方案完成后，总结报告要不要提前列提纲？"

### 代拟偏好（从修改反馈学习，直接套用）
- 领导偏好：先结论后依据 / 不用"我局认为" / 段落≤5 行 / …
- 格式偏好：字体字号 / 是否要溯源卡 / 文号格式
- 口径偏好：单位自称"我局" ▏"中心" ▏"本单位"

### 提醒偏好
- 提前量：周期材料提前 N 天提醒（默认 3 天）
- 提醒方式：会话开场一句话（不打断）
```

## 一、画像数据模型（v7.1.1 基础段，保持不变）

```markdown
# 公文用户画像（user-profile.md）
> 由公文大师自动维护。更新时间：{YYYY-MM-DD HH:MM}｜置信度：{高/中/低}

## 单位与身份（置信度: 高=用户明示 / 中=对话推断 / 低=泛化）
- 单位名称：地方数据局（明示）
- 单位类型：政府部门 ▏党委 ▏事业单位 ▏国企 ▏乡镇街道 ▏其他
- 行政级别：正处 ▏副处 ▏正科 ▏科员 ▏ uncertain
- 岗位职责：办公室主任/文字岗/业务岗（用户自述原话："我负责办公室材料"）

## 行文偏好
- 常用文种：通知、请示、工作总结（按历史使用频次自动累积）
- 风格倾向：稳重规范 ▏简明扼要 ▏喜欢用数据 ▏（从修改反馈中学习）
- 上级要求：如"局长喜欢先结论后依据"（用户反馈原话）
- 红线禁忌：如"不要用'我局认为'"（负空间，从纠错中沉淀）

## 材料历史
- {YYYY-MM-DD}：工作总结（季度）｜满意度反馈：改 2 轮
- {YYYY-MM-DD}：立项请示｜反馈：一次过

## 待澄清（下次对话可顺势问）
- 单位全称的规范写法？
- 是否有地方模板/格式要求？
```

## 二、主动引导采集（渐进式，不打扰）

### 触发时机
1. **首次使用**（无 user-profile.md）→ 触发「认识一下」引导；
2. **画像空白项**（如"单位类型"未知）→ 在**写完一份材料后**顺势问一句，不单独打断；
3. **画像冲突/过期** → 标注待澄清。

### 引导对话原则（源自外部最佳实践）
- **一次最多 2 个问题**，选择题优先于开放题；
- **绑定写作任务问**（"写好这份通知。对了，这份是发给系统内单位还是社会单位？——记下来以后行文口径就固定了"），不做纯问卷；
- **明示价值**（"记下这些后，下次不用再解释单位性质，文风自动贴合"）；
- **10-15 分钟达成 60% 覆盖**即可用，不追求一次问全。

### 标准引导话术（首次）

```
第一次用公文大师？先花 30 秒认识一下，之后的每一份材料都会更贴合你的情况：

1. 你在什么单位？（如"地方数据局"/"XX镇人民政府"）
2. 单位是什么类型？（a 政府部门 b 党委机关 c 事业单位 d 国企 e 乡镇街道 f 其他）
3. 你主要负责什么？（如"办公室材料" "业务科室日常公文"）

——也可以跳过，直接说你要写什么；我们边写边补。
```

## 三、背景沉淀规则（写入/更新/加载）

### 存储
- 位置：`user-profile.md`（与用户工作区/数据同层；standalone 场景在 skill 包根，多用户场景每用户一文件）；
- 格式：Markdown（人类可读可改，与外部最佳实践 USER.md 模式一致，不用数据库）；
- 大小预算：≤ 2KB（高频字段常载，低频归档）。

### 更新触发（增量，只增不删历史）
| 信号 | 动作 |
|---|---|
| 用户明示单位/岗位/级别 | 写入，置信度=高 |
| 对话推断（如用词习惯暗示级别） | 写入，置信度=中，标注推断 |
| 用户修改了 AI 产出（纠正措辞/格式） | 沉淀到「红线禁忌/上级要求」 |
| 历史材料完成 | 追加「材料历史」一行 |
| 与已有画像冲突 | 新值覆盖+旧值挪到"待澄清"注明 |

### 加载规则
- 每次写作会话**开头自动读 user-profile.md**（≤2KB 无负担）；
- 画像中置信度=低的字段只作参考，不直接决定文风。

## 二点五、私人秘书服务层（v7.1.2 核心，四大能力）

### 能力 1：公文日历主动预告

**学习机制**：从「材料历史」自动归纳周期规律——同文种出现 ≥3 次且间隔规律（如每月 1 篇月报）→ 自动生成日历条目。

**预告规则**（会话开场一句话，绝不打断）：
- 到期前 N 天（默认 3，可配）："按您的习惯，月度工作报告通常 5 号前交——需要现在列提纲吗？"
- 季节节点（内置公文日历）：1 月年度总结+预算申报季提醒；3/6/9/12 月末季度总结季提醒；12 月考核季提醒。
- 用户说"不要提醒" → 停止该条目（尊重边界）。

### 能力 2：代拟偏好直接套用

**学习机制**：用户对产出的每次修改都是偏好信号——
- 删了"我局认为" → 红线禁忌
- 调整了段落顺序为"结论先行" → 上级偏好
- 修改了字号/边距 → 格式偏好

**应用规则**：下次起草直接套，不问不确认；成稿附一行"已按您的偏好：先结论后依据、无「我局认为」"——让用户知道秘书在用心，可一键纠偏。

### 能力 3：多材料串联（专项视野）

**机制**：进行中专项记录关联材料链。当用户再写相关材料时：
- 主动关联："这份整改方案和你上周的验收申请是同一个专项——口径已对齐。"
- 提前铺排："专项还差总结报告，要不要现在列提纲备用？"
- 口径一致性检查：引用同一专项此前材料的关键数据/表述，防止前后矛盾。

### 能力 4：会话开场秘书简报（可选开关，默认开）

写作会话开始时，画像加载后输出 ≤3 行简报（不喧宾夺主）：

```text
秘书简报：
· 距月报惯例提交日还有 2 天
· 上次的立项请示已一次过——本季材料质量稳定
· 「XX专项」进行中：整改方案待办
（今天要写什么？或直接说需求）
```

无到期事项/无专项时只输出 1 行："画像已加载（{n} 条偏好）。今天写什么？"

### 边界与红线

- **秘书不替用户做决定**：预告/提醒/建议，绝不自动代写未要求的材料；
- **隐私**：画像文件属于用户，可随时查看/编辑/删除；敏感信息（如领导个人评价）标注「私密」，导出时脱敏；
- **降噪**：无新信号时简报合并为 1 行；连续 2 次用户忽略提醒 → 该提醒降频（间隔翻倍）。

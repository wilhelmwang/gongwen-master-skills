# 部门职责 → 定制公文流程场景生成指引（duty-to-scenario）

> 目标：拿到部门职责材料后，为**每个部门**生成贴合其职权的定制公文流程场景。
> 本文档定义生成规则，供 agent 执行（也可由用户指定部门直接触发）。

## 生成原理

```
部门职责（用户提供的职责摘录）
  ├─ 提取「职权动词」：审批/核准/备案/监管/评审/批复/评定/验收…
  │   → 判断该部门在流程中的角色：审批方 / 监管方 / 被服务方
  ├─ 提取「职能领域」：数据/财政/人事/规划/项目…
  │   → 匹配基础场景线（project-approval / it-project / …）
  └─ 输出定制场景卡：{部门}视角的「对外行文清单 + 对内收文清单」
```

## 场景卡生成模板（每个部门一张 `{org}-scenarios.md`）

```markdown
# {部门全称} 公文场景指南

> 职责依据：{source_url}（{published} 发布）

## 一、对外发文场景（本部门作为审批/监管方的公文）

| 下级/相对单位找本部门办的事 | 需要对方提交的公文 | 本部门回复的公文 |
|---|---|---|
| （从职责"审批/核准/批复/评审"条目提取）| 请示/申请/报批文 | 批复/审核意见/许可决定 |

## 二、对上行文场景（本部门作为申报方的公文）

| 本部门要办的事 | 报送对象 | 公文文种 |
|---|---|---|
| （从职责"拟订/组织/推动"条目提取，涉资金/项目/编制）| 政府/上级主管部门 | 请示/报告/方案 |

## 三、平级协同场景

| 协同事项 | 函件类型 | 对口部门（机构实名，用户提供）|
|---|---|---|

## 四、高频专班场景（按职能定制）

（如数据局：政务信息化项目技评/数据共享审核；财政局：预算评审/财评…）
```

## 示例：某市数据主管部门（已提供职责 11 条）

职责第七条「审核市级政务信息化项目」→ 审批方场景：
- 对外收文：各单位报「政务信息化项目立项申请（请示）」+「建设方案」→ 数据局出「技术评审意见」+「立项批复」
- 职责第一、七条「统筹数字政府建设」→ 政策发文场景：以数据局名义出「全市政务信息化项目年度计划编制通知」

## 执行方式（agent 用）

1. 用户点名部门（"给财政局生成场景"）→ 依据用户提供的职责材料 → 按模板生成场景卡；
2. 无职责材料 → 请用户补充职责摘录，或按通用职权推导并在场景卡上标注「待核」；
3. 生成后落到 `govdoc-workflow/references/scenarios/departments/{org}-scenarios.md`；
4. 门禁回归（validate/verify/回归）。

## 批量生成策略

- 优先级：被高频流程引用的节点部门（发改委/数据局/财政局/政务服务局/住建/自然资源）先行；
- 预算公开页（sjj/rsj/wjw/czj.local.gov.cn 等每年 1-2 月更新）是职责+内设机构的批量来源，页内「第一部分主要职责」「第二部分机构设置」结构稳定，可正则批量抽取；
- 每生成一批跑一次门禁，确保 SKILL 引用不悬空。

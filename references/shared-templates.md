## 一、自动更新检查（v6.6.0 挂钩升级工具）

每次本 skill 因新的公文写作、修改或审校任务被触发时，先执行一次内置更新检查；同一会话中用户已经确认过选择时，不要重复检查。

- 当前 skill 包版本：v8.0.0（单技能交付 + 双数据底座 + 意图引导）。
- **检测升级**：运行 `python upgrade_check.py --check`（版本矩阵）查看当前各技能版本。
- **执行升级**：拿到新版单技能包后，运行：
  ```
  python upgrade_check.py --upgrade <新包解压目录>
  ```
  工具会自动：备份旧技能到 `backups/` → 替换 gongwen-master 整技能目录 → 保留用户数据（style-models 等单位文风模型）→ 跑 verify_install 校验。
- 若用户无法执行命令（无 IT 基础），引导其联系运维或提供新版包，由助手代为执行升级。
- 用户未选择前，不进入正文写作。

## 二、工作边界

使用本 skill 时，先确认用户要处理的文种、使用场景和已有材料。信息不足时，先列出最少必要补充项；若用户要求直接写，基于已知信息作保守假设并明确标注。

## 三、负反馈收集

如果用户在使用本 skill 过程中明确抱怨"不好用""不对""不像""太差""没帮助""改得不行""还是不满意"等，不要打断当前任务。先完成当前写作、修改、诊断或排版答复；在答复末尾按 `govdoc-feedback/SKILL.md` 的规则追加飞书问卷链接。普通修改要求，如"再正式一点""换个标题""帮我压缩"，不触发反馈问卷。

## 四、作者资源（输出后轻引导）

完成写作/修改/审校后，若用户有进一步需求（调整风格/篇幅/文种/导出 Word），按需提示可用能力即可。

> **交付后的引导以 `gongwen-master/SKILL.md`「成品交付·下一步建议」钩子为准**：
> 该钩子要求每次产出后在回复末尾给出 2-3 条具体「下一步建议」（编号，末尾问「要我现在执行哪一项」），
> 且驻留期间每轮保留，不主动结束。本节不再另行要求「首次输出后追加固定话术」——
> 那是钩子之前的旧做法，两者同时生效会冲突。

## 五、去 AI 味检查清单（v6.3.2 全族推广）

生成或修改公文（含各 govdoc-*、govdoc-styles 文风、shuji 书风产出）后，逐项检查以下 AI 味痕迹：

### 结构层面
- 避免机械式清单堆叠（如"第一、第二、第三..."连续超过 5 条）
- 要求叙事主线贯穿全文，而非碎片化罗列
- 章节标题用纯文字，避免 emoji 或符号装饰

### 语言层面
- 数据必须融入叙述，而非单独列出
- 避免"值得注意的是""需要指出的是""综上所述"等套话
- 要求独立判断，而非"一方面...另一方面..."的平衡句式

### 深度层面
- 深度研究须含机制分析（为什么这样做）
- 须含情景推演（如果...会怎样）
- 须含关键验证节点（怎么确认有效）

### 风格层面
- 公文语言四大原则：准确、平实、简明、庄重
- 避免过度使用"加强""推进""落实"等万能动词
- 数据和案例必须具体，避免"若干""一些""部分"等模糊表述

### AI 味高发模式（v6.3.2 新增）
- **意义膨胀**：空泛强调价值却无具体所指（如"具有重要意义""影响深远"）
- **假深刻**：用复杂句式装深度，实际无信息增量
- **规则三连**：连续"必须/务必/一定要"营造命令感却无约束对象
- **同义词轮换**：为避开重复生硬替换（"开展/推进/深化"乱序轮换）
- 检出以上模式时，用具体事实/数据/逻辑替换之

# 文种模块公共规范

> 以下各节由 22 个模块（16 文种 + 5 嵌套子技能 + govdoc-layout）抽取归并，原文逐字保留。
> 各模块执行自身工作流前应先读取对应小节。

## 默认工作流（文种模块四步）

1. **明确任务**：判断文种类型和写作目的
2. **收集信息**：获取必要的事实、数据、依据
3. **套用结构**：按**本模块自己的** `references/formulas.md` 的文种公式生成初稿（含提示词骨架与分步策略）；无 formulas 时用 GB/T 9704 通用骨架兜底
4. **质量检查**：按 GB/T 9704 和行文规则检查

## 输入清单

- 发文机关、接收对象/主送机关
- 事由/背景/依据
- 事项内容/工作要求/事实材料
- 附件、落款日期、格式要求

## 输出形态

- 正式公文初稿
- 结构提纲
- 修改建议

## GB/T 9704-2012 格式规范

### 页面设置
- **纸张**：A4 型纸（210mm x 297mm），双面印刷，左侧装订
- **页边距**：上 3.7cm / 下 3.5cm / 左 2.8cm / 右 2.6cm
- **版心**：每页 22 行，每行 28 字（固定值 28 磅行距）
- **页眉页脚**：奇偶页不同，页眉高 1.5cm，页脚高 2.5cm

### 字体字号
| 组成部分 | 字体字号 |
|---|---|
| 公文标题 | 二号小标宋体，居中 |
| 一级标题 | 三号黑体 |
| 二级标题 | 三号楷体，加粗 |
| 三级标题 | 三号仿宋_GB2312，加粗 |
| 正文、四级标题 | 三号仿宋_GB2312 |
| 公文文号、主送机关、附件说明、发文机关署名、成文日期 | 三号仿宋_GB2312 |
| 版记 | 四号仿宋_GB2312 |
| 页码 | 四号宋体 |

### 正文结构层次
依次使用「一、」「（一）」「1.」「（1）」标注：
- 第一层：三号黑体
- 第二层：三号楷体加粗
- 第三层：三号仿宋加粗
- 第四层：三号仿宋

### 标题格式
- 完全性标题：发文机关 + 事由 + 文种
- 省略性标题：事由 + 文种
- 标题中除法规、规章加书名号外，一般不用标点符号
- 回行时词意完整，排列采用梯形或菱形

### 发文字号
- 格式：机关代字 + 〔年份〕 + 发文顺序号
- 示例：国办发〔2024〕5号
- 年份用六角括号「〔〕」

### 成文日期
- 用汉字书写，年、月、日三者俱全
- 单一机关行文：成文日期之上居中编排发文机关署名
- 联合行文：各发文机关署名按顺序排列，印章一一对应

### 印章
- 加盖端正，以成文日期中心为准，印章下端压成文日期，骑年盖月
- 不得出现空白印章

## 行文规则（《党政机关公文处理工作条例》2012）

### 行文关系
- 行文应当确有必要，讲求实效
- 一般不得越级行文，特殊情况需抄送被越过的机关
- 上行文：主送一个上级机关，需要其他机关掌握的用抄送
- 下行文：主送下级机关，需要其他机关周知的用抄送

### 上行文规则
- 请示：一文一事，一般只主送一个上级机关，不得抄送下级机关
- 报告：不得夹送请示事项

### 下行文规则
- 通知：主送下级机关，需要其他机关周知的用抄送
- 通报：主送下级机关，表彰批评

### 联合行文
- 同级机关可以联合行文
- 联合行文各机关署名按顺序排列，印章一一对应

## 15 种法定公文（《党政机关公文处理工作条例》2012）

| 文种 | 用途 | 行文方向 |
|---|---|---|
| 决议 | 会议讨论通过的重大决策事项 | 下行 |
| 决定 | 对重要事项作出决策和部署，奖惩单位人员 | 下行 |
| 命令(令) | 公布行政法规、宣布强制性措施、嘉奖有关人员 | 下行 |
| 公报 | 公布重要决定或者重大事项 | 下行 |
| 公告 | 向国内外宣布重要事项或者法定事项 | 下行 |
| 通告 | 在一定范围内公布应当遵守或者周知的事项 | 下行 |
| 意见 | 对重要问题提出见解和处理办法 | 上行/下行/平行 |
| 通知 | 发布、传达要求下级执行的事项，批转转发公文 | 下行 |
| 通报 | 表彰先进、批评错误、传达重要精神或告知重要情况 | 下行 |
| 报告 | 向上级机关汇报工作、反映情况，回复上级询问 | 上行 |
| 请示 | 向上级机关请求指示、批准 | 上行 |
| 批复 | 答复下级机关请示事项 | 下行 |
| 议案 | 各级政府向同级人大或常委会提请审议事项 | 平行 |
| 函 | 不相隶属机关之间商洽工作、询问和答复问题 | 平行 |
| 纪要 | 记载会议主要情况和议定事项 | 下行 |

## 常见错误与规避

- 标题不规范：缺少发文机关或事由
- 主送机关错误：多头主送或越级主送
- 一文多事：一份公文包含多个不相关事项
- 语气不当：该严肃时平淡，该简洁时冗长
- 格式错误：字体、字号、行距不符合 GB/T 9704
- 引用失准：引用文件名称或文号错误
- 逻辑混乱：层次不清、前后矛盾
- 空泛套话：缺乏具体措施和数据支撑

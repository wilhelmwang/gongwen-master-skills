# 公文大师 · 团队模式编排手册（team-orchestration v1.1 · 2026-09-23）

> 团队模式的两条腿之一：**评审**（本手册）。另一条腿是**写稿**（`team-writing.md`，v8.1.0 新增）。
> 原则：**编排与执行分离**——主理人只编排、不代写；专家独立上下文、并行/串行按场景；共享工作区中转，主理人只读 manifest。
> 平台能力：WorkBuddy TeamCreate / Agent 派遣（session 内实例化；本手册保证会话间一致）。
>
> **两腿的分工**：评审腿=成品进、意见出（本手册）；写稿腿=需求进、正文出（`team-writing.md`）。
> 两条腿共用本手册的主理人契约、信息隔离与门禁规则；写稿腿的差异（执笔权归秉笔、骨架须用户确认、涉密退出）见 `team-writing.md` 第七节。

## 一、主理人契约（Master Orchestrator）

1. **只编排，不执行**：主理人负责意图裁决、阶段门禁、专家派遣、结果综合；**不亲自撰写正文**。
   - 评审场景：主理人只出综合报告 + 汇签。
   - **写稿场景（v8.1.0）**：主理人**仍不执笔**——执笔权在**秉笔**（见 `team-writing.md`）。主理人负责判级、把秉笔的骨架契约转呈用户确认、阶段门禁与最终汇签。两个角色不得混同。
2. **门禁规则**：每阶段交付物未达验收标准（见场景契约）→ 打回专家修订 ≤2 轮；仍不达标 → 上报用户决策，不无限循环。
3. **信息隔离**：专家间不直接通信；主理人中转上下文；后序专家不预知前序结果（防交叉污染，核查场景强制）。
   - 写稿场景的隔离按拓扑分档，见 `team-writing.md` 第七节第 5 条（T3 竞稿必须隔离，T2 分笔不看彼此成品）。
4. **共享工作区**（≥4 专家时启用）：
   ```
   .gongwen-team/{session}/phase-1/{role}-report.md …
   manifest.yml     # 各阶段状态/路径/结论摘要——主理人只读 manifest，不读全文
   ```
5. **输出契约**：
   - 评审场景：综合报告（各专家意见 + 裁决理由）+ 成品稿/修订稿 + 遗留项清单。
   - 写稿场景：成品稿 + 写稿溯源表 + 缝合说明（T2/T4）+ 遗留项清单。
6. **成本纪律**：仅当场景判定为「团队模式」才组建团队（规则 F 触发），日常写作禁止组建；
   写稿模式**仅显式点名启用**，模糊授权不进。

## 二、专家角色包（能力 = 现有技能零改造；角色雅名见 `team-roster.md`）

### 评审角色（评审腿专用）

| 角色 | 能力载荷 | 输入 | 输出 |
|---|---|---|---|
| 文种专家 | govdoc-{文种}（16 个按需） | 需求+初稿 | 文种合规意见（结构/要素/格式） |
| 风格专家 | govdoc-styles / shuji（16 风格） | 文本+风格要求 | 风格适配意见（文风/句式/语料口径） |
| 数据专家 | qiushi-db（hybrid3/论断/地方） | 需引用点清单 | 引用建议（权威表述+页码溯源） |
| 质检专家 | govdoc-polish（质检模式） | 成品稿 | P0/P1/P2 质检报告（5 维评分） |
| 核查专家 | article-review（模式 B） | 文章/材料 | 事实核查报告（声明-证据级） |

### 写稿角色（写稿腿专用 · v8.1.0）

| 角色 | 能力载荷 | 输入 | 输出 |
|---|---|---|---|
| **秉笔**（总纂） | govdoc-{文种} + formulas.md + 指定文风 | 需求 + 佐笔/分笔产出 | 骨架契约 / 成品稿 / 缝合稿 + 溯源表 |
| **分笔**（笔手） | 目标文种体例 + 指定文风 | 一个槽位（构件/篇幅/证据/语脉锚点） | 槽位段落（按六项收口） |

> 写稿腿的**佐笔**复用评审腿的数据/风格角色（据实/法鉴/笔致），但它们只供要素、不出正文；
> **竞稿者**复用会诊角色（章策/城构/枢垣，各绑一种文风）。详见 `team-writing.md` 第二节。

派遣规则：场景契约按角色标识派遣（评审：orchestrator/doc-expert/style-expert/data-expert/qc-expert/verify-expert；
写稿：orchestrator/writer-lead/writer/data-expert/style-expert），雅名绑定见 `team-roster.md`；场景契约指定角色集合；
角色拾取现有技能 SKILL.md 作为自身指令（`references/team-scenarios.md` 场景表）。

## 三、触发（规则 F）

请求含下列任一信号 → 进入团队模式（主理人接管）：

**评审腿**：
**评审腿**（本手册）：
- 评审/把关/多视角/会诊/交叉评审/重要材料/正式汇报把关/深度核查/政务要情质检
- 或用户显式要求「让专家团队看看/多个人审一下」

**写稿腿**（`team-writing.md` · v8.1.0）：
- 一起写稿/团队写稿/多人合写/专家团写稿（T1）｜分段承包/分头写/分工写（T2）
- 各写一版/竞稿/多版选优（T3）｜全程合写/骨架会战/分层合写（T4）
- **仅显式点名启用**；「你看着办」这类模糊授权不进；S 级单文种短件不启用

## 四、会话内实例化模板（供主理人执行）

**评审腿**：
```
1. 读取本手册 + team-scenarios.md，判定场景（1/2/3）
2. 按场景契约 TeamCreate（或逐专家派遣）→ 每个专家注入角色包指令
3. 共享工作区分配（专家写入 reports/）
4. 依次/并行完成阶段 → 主理人读 manifest 裁决 → 汇签
5. 交付综合报告 + 成品 + 遗留项
```

**写稿腿**（详见 `team-writing.md` 第四节）：
```
1. 读取 team-writing.md + team-scenarios.md，判定拓扑（4/5/6/7）
2. 秉笔出骨架契约 → 主理人转呈用户 AskUserQuestion 确认（硬要求，不得跳过）
3. 按拓扑派遣佐笔/分笔/竞稿者 → 收产出
4. 秉笔成文/缝合 → 主理人门禁
5. 交付成品 + 写稿溯源表 + 缝合说明
```

## 附：机关流程对应说明（架构来源）

本团队结构系**机关公文流程的数字化投影**（对照《党政机关公文处理工作条例》拟制流程）：

| 机关机构/角色 | 环节 | 团队对应（评审腿） | 团队对应（写稿腿 · v8.1.0） |
|---|---|---|---|
| 分管/主要领导 | 审签→签发（终决权） | 用户本人（人工终签） | 用户本人（人工终签） |
| 办公厅主任/秘书长 | 统筹核签、进度裁决 | 文衡（主理人） | 文衡（主理人，仍旧只编排） |
| **业务司局（拟稿人）** | **起草** | — | **秉笔（总纂·唯一执笔点）** |
| 政策研究室 | 讲话/报告起草、政策阐释 | 风格专家（govdoc-styles/shuji） | 笔致（佐笔·语料口径）+ 分笔（指定文风） |
| 相关部门参与起草 | 分段起草 | — | 分笔（笔手·承包槽位） |
| 办公厅（室）核稿岗 | 核稿：文字/格式/体例 | 校书（质检）+ 章仪（格式） | 同左（写后交评审） |
| 信息处/统计部门 | 数据支撑、口径校准 | 据实（qiushi-db） | 据实（佐笔·供数据要素） |
| 法规处/法制办 | 合法性审查 | 法鉴（涉法材料强制） | 法鉴（佐笔·供政策依据） |
| 相关部门会签 | 会签征求意见 | 场景 1 多专家并行 | 场景 4/T1 佐笔并行 |
| 文印室/机要室 | 缮印、分发、归档 | govdoc-layout（排版） | 同左 |

> **v8.1.0 修正名实不符**：原表把「业务司局（拟稿人）→ 起草」映射为「文种专家（govdoc-*）」，
> 但文种专家在本包实现里只做评审、不执笔（红线："不修改原文，只出意见"），名实不符。
> 本次新增写稿腿后，**起草环节正式对应秉笔**，映射表与实现一致。
>
> 使用价值：宣讲/交付时可直接对照此表说明架构合理性；**人在环终签**与真实签发权制度一致。

## 派单分级表（S/L/M/H · v6.6.0 单一入口 · v8.1.0 增写稿列）

| 级 | 判定（主理人依据规则 A-F） | 动作 | 成本 | 交付 |
|---|---|---|---|---|
| S | 单文种命中规则 A，无润色/质检/引用附加 | 文衡直办（现有方法论）；**写稿模式不启用** | 1x | 成品 + 下一步建议 |
| L | 单文种 + 一个附加动作（润色/质检/引用其一，规则 E/C） | 文衡 + 1 专家 | 2-3x | 成品 + 专家意见 |
| M | 多视角/会诊/涉法（规则 F 关联 B/会诊/涉法）；或**写稿 T1** | 多专家并行 / 秉笔 + 佐笔 | 3-8x | 综合意见 + 裁决 / 成品 + 溯源表 |
| H | 重要材料/正式汇报把关/深度核查（规则 F）；或**写稿 T2/T4** | 全团队 + 法鉴（场景 1 全量/场景 3）/ 分笔并行 + 秉笔缝合 | 10x+ | 综合报告 + P0/P1/P2 / 成品 + 缝合说明 |
| H+ | 大型材料（报告级）；或**写稿 T3** | T4 + 评审团串联 / 多版竞稿（成本 ×N） | 15x+ | 全链交付 + 溯源 |

> 判级原则：**先看附加要求再升级**——单文种无附加 = S；每多一个动作维度升一级；
> 用户显式要求"把关/会诊/核查"直达 M/H；显式点名写稿模式按拓扑定 M/H/H+。

# 公文大师 · 团队模式场景契约（team-scenarios v2.0 · 2026-09-23）

> **团队模式统一派单入口**：七场景，分两腿。
> **评审腿（场景 1-3）**：成品进、意见出——编排细节见 `team-orchestration.md`。
> **写稿腿（场景 4-7）**：需求进、正文出——编排细节见 `team-writing.md`。
> 主理人（文衡）按本表定位场景后派遣；两腿共用主理人契约、门禁与信息隔离规则。

## 场景 1：重要公文多视角评审（默认评审场景）

| 项 | 内容 |
|---|---|
| 触发 | 正式汇报/对外发布/领导讲话等重要材料 + 评审信号（"把关""审一下""多视角看看"） |
| 专家集合 | 文种专家 + 风格专家 + 数据专家（待引用点 >0 时）+ 质检专家 + **法鉴**（涉法规/制度/上位法材料强制）|
| 流程 | ①主理人判定文种与要点 → ②文种专家 审结构/要素 → ③风格专家 审文风适配 → ④数据专家 核引用（可选）→ ⑤质检专家 出 P0/P1/P2 报告（5 维）→ ⑥主理人综合裁决 → 输出修订建议清单 |
| 验收 | 每专家交付 ≤1 页书面意见（意见+证据+可执行修改）；综合报告含"采纳/驳回"裁决理由 ≥80% 建议给出处理；质检专家意见须含明密级标识/保密合规章节 |

## 场景 2：跨风格会诊（三笔会诊升级为并行）

| 项 | 内容 |
|---|---|
| 触发 | "会诊""让文风一/2/3 都看看"（规则 B 已路由 govdoc-styles → 本场景接手） |
| 专家集合 | 风格专家×3（文风一/2/3 独立上下文，互不知情） |
| 流程 | ①三专家并行独立评审同一稿（结构/文风/表达 DNA 口径）→ ②主理人汇总对比（共识/分歧矩阵）→ ③分歧点加权裁决（语料口径权重）→ ④输出联合意见 |
| 验收 | 三份独立意见可溯源；对比矩阵含共识 ≥3 条与分歧 ≤5 条；以引用的语料证据为裁决依据 |

## 场景 3：文章/材料深度核查（复用 fact-check-team）

| 项 | 内容 |
|---|---|
| 触发 | "核查这篇""查证事实""这篇有没有问题"（规则 E 已路由 article-review → 模式 B） |
| 专家集合 | 沿用 fact-check-team 五专员（内容数据核查/逻辑谬误/事实研判/风险评分/报告编译）+ 主理人 |
| 流程 | ①TeamCreate + 声明标记 → ②专员并行核查（信息隔离强制）→ ③事实研判正/反/修正 → ④风险评分 → ⑤编译 P0/P1/P2 报告 |
| 验收 | 报告含结论前置对比表、每条问题附证据与修复建议；原子声明覆盖率 ≥90% |

# 写稿腿（v8.1.0 新增 · 场景 4-7）

> 通用硬约束（四场景共守，细则见 `team-writing.md`）：
> ① **执笔单点收敛**——正文只经秉笔一人的手；② **Phase 0 停机**——秉笔出骨架契约后必须打印
> `【等待用户确认骨架】`并结束，主理人取得**用户真实回答**前不得派佐笔/分笔（v8.1.1 硬门禁，
> 禁以"用户沉默/你看着办/模型自写的已确认"代替确认，见 `team-writing.md` 三·五节）；
> ③ **交付前篇幅校准**（v8.1.2 硬门禁·四拓扑通用）——正文实际字数与骨架区间比对，偏离 >10% 先补/删，
> 见 `team-writing.md` 五·五节（T1 无缝合也要做）；
> ④ 缺料标【待补】，禁用估算值或套话填充；⑤ **涉密材料退出写稿模式**（多专家走 LLM，文本外发）。

## 场景 4：主笔 + 佐笔（T1 · 推荐默认）

| 项 | 内容 |
|---|---|
| 触发 | "一起写稿""团队写稿""多人合写""专家团一起写/写稿"（规则 F 命中，拓扑不明时默认 T1） |
| 专家集合 | 秉笔（执笔）+ 佐笔按需（据实=数据 / 法鉴=政策依据 / 笔致=语料口径） |
| 流程 | ①秉笔收需求 → 出**骨架契约** → ②主理人转呈用户 AskUserQuestion 确认 → ③佐笔**并行供要素**（只出可引用条目 + 证据锚点，不出正文）→ ④秉笔吃料**一次成文**（不拼接）→ ⑤可选：交评审团（场景 1） |
| 验收 | 骨架契约已获用户确认；成稿逐段可溯源到供料角色（写稿溯源表）；正文一次成文无拼接痕迹 |
| 成本 | M（3-8x） |

## 场景 5：分工承包（T2）

| 项 | 内容 |
|---|---|
| 触发 | "分段承包""分段写""分头写""分工写" |
| 专家集合 | 秉笔（定骨架 + 缝合）+ 分笔×N（各承包一个分论槽位） |
| 流程 | ①秉笔定骨架契约（含每槽**语脉锚点**）→ 用户确认 → ②分笔并行各写一槽（按槽位契约六项收口）→ ③秉笔**缝合**（过渡必重写、语脉校验、撞车检测、口径统一、篇幅校准）→ ④可选评审团 |
| 验收 | 五条缝合规则全达标；分笔不看彼此成品；缝合说明随交付（≤10 行） |
| 风险 | **缝合处易拼盘**——仅在分论间无强语脉依赖时用；需一气贯通的排比递进改用 T1 |

## 场景 6：多版竞稿（T3）

| 项 | 内容 |
|---|---|
| 触发 | "各写一版""竞稿""多版选优""写几版挑一版" |
| 专家集合 | 竞稿者×N（复用章策/城构/枢垣，各绑一种文风）+ 秉笔（择优定稿） |
| 流程 | ①秉笔定硬要求（文种/主题/篇幅/场合），**不写骨架** → ②竞稿者**并行隔离**各写全篇 → ③秉笔择优定稿 |
| 验收 | 各版完整独立；**默认选优不融合**；用户要求融合时按「重写」对待并明说 |
| 成本 | H+（**×N**，N 倍成本）；公文语体下"选优"主观性强，建议仅重要材料使用 |

## 场景 7：分层混合（T4）

| 项 | 内容 |
|---|---|
| 触发 | "全程合写""骨架会战""分层合写" |
| 专家集合 | 骨架会战（多专家）+ 秉笔（裁定骨架/独写首尾/缝合）+ 分笔×N（主体分包） |
| 流程 | ①骨架会战并行出方案 → 秉笔裁定统一骨架 → 用户确认 → ②分笔并行写主体分论 → ③**秉笔独写**开头/结尾/过渡（语脉最吃功夫处，绝不外包）→ ④秉笔缝合 → ⑤可选评审团 |
| 验收 | 首尾与过渡确由秉笔独写；缝合五规则达标；溯源表完整 |
| 成本 | H+（大型材料级，15x+） |

## 派遣速查

```
团队模式信号 → 场景判定：
  【评审腿】
    评审/把关/多视角/重要材料 → 场景 1（多视角评审）
    会诊/交叉评审             → 场景 2（跨风格会诊）
    核查/查证/有没有问题       → 场景 3（深度核查）
  【写稿腿】（仅显式点名）
    一起写稿/团队写稿/多人合写/专家团写稿 → 场景 4（T1 主笔+佐笔，默认）
    分段承包/分头写/分工写     → 场景 5（T2 分工承包）
    各写一版/竞稿/多版选优     → 场景 6（T3 多版竞稿）
    全程合写/骨架会战/分层合写  → 场景 7（T4 分层混合）
    命中写稿但拓扑不明          → 问一句，默认 T1
  【串联】
    写后审：先走场景 4-7 出稿 → 再交场景 1 评审（秉笔不参与对自己成稿的评审）
  其他 → 单智能体主路径（不组建团队）
```

> **触发纪律**：写稿腿**仅显式点名启用**——"你看着办""随便写写"这类模糊授权不进；
> S 级单文种短件（如一条通知）不启用写稿模式，走主理人直办。
